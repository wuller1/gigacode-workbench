# Browser / Design: покрытие интерактивного макета

Статус: прототип для согласования. `app/` не менялся. Runtime-реализация остаётся заблокированной до согласования полного макета пользователем. Наличие работающей кнопки в этом HTML не подтверждает готовность backend.

Модуль: `suite-prototype-browser-design.js`; стили подключаются им автоматически из `suite-prototype-browser-design.css`. Подключать **после** исходных скриптов страницы и общей оболочки `SuitePrototype`, если она есть. Старые DOM-узлы сохранены скрытыми для совместимости с прежними обработчиками переключения проекта.

## Ручной маршрут проверки

1. Открыть Browser: сделать вторую вкладку, повторить тот же URL, убедиться что третьей нет. Переименовать через контекстное меню и двойной клик. Закрыть активную, восстановить из истории. Стрелки на tablist работают.
2. Выбрать другой проект, создать свою вкладку; вернуться и проверить прежнюю активную. Reload страницы сохраняет вкладки проекта.
3. Ввести два разных адреса в одной вкладке; проверить назад/вперёд. URL не должен означать настоящую загрузку.
4. Открыть размер: mobile → повернуть → свой размер → zoom → авто. Ошибочные размеры 0/9999 не принимаются.
5. Сделать иллюстрацию снимка, открыть её, добавить в материалы. Проверить все три devtools вкладки и детали запроса.
6. У каждого диалога проверить ×, Escape, внешний клик, возврат фокуса. У браузерного меню проверить возврат после выбора.
7. Переключить задачи и проверить изоляцию brief/материалов/комментариев. UI Kit и publication остаются общими в проекте. Переименовать проект: previousProject event сохраняет его данные.
8. Design: шесть состояний × две темы × три размера, комментарий/решение, brief, измерение и появление отчёта в материалах.
9. Материалы: поиск, фильтры, создание, текстовая правка, новая версия, переименование, архив/восстановление, экспорт собственного файла.
10. UI Kit: поиск и очистка, компонент и его состояния, кнопка/поле/select, токены, SVG export, шаблон→материал.
11. Публикация: изменить назначение, подготовить локальное ревью, открыть/отметить готовым, экспортировать handoff. Не утверждать, что в Git что-то создано.

Проверено в текущем срезе автоматически: `node --check design/suite-prototype-browser-design.js` проходит. Живое визуальное тестирование выполняет основной агент; только после него фиксировать UI evidence. Это список покрытия и ограничений, не отметка прохождения всего маршрута.

## Контракт общей оболочки

`SuitePrototype.project()` — имя проекта; `task()` — стабильный ключ задачи; `session()` — выбранный разговор; `ask(text)` — подготовить поручение в чат. Событие `suite:scope-change` слушается на document, detail `{project,task,session,previousProject?}`, bubbles=true. Rename переносит localStorage state из previousProject. Подписки на window не дублируются. Если task() возвращает изменяемый заголовок вместо стабильного ключа, host должен адаптировать его, чтобы переименование задачи не создавало новый контейнер материалов.

Неактивный rename: модуль отдельно обрабатывает `suite:project-renamed` `{previousProject,project}`, чтобы переносить Browser/Design state, даже когда пользователь переименовал другой проект в списке.

## После независимого аудита общего shell

- Повторные `suite:scope-change` без смены project/task больше не перерисовывают поля Browser/Design и не стирают адресный черновик при завершении агентского demo-хода. Адресный черновик также сохраняется по вкладке; Escape возвращает подтверждённый URL. Ручной ввод прекращает демонстрацию агентского курсора.
- Вложенные диалоги сохраняют исходную точку возврата фокуса; reload не выдаёт сохранённый agent-active flag за живого исполнителя.
- `suite:artifact-open` поддерживает `{id,name}` и открывает материал **текущей задачи**. Неизвестный ID показывает отсутствие записи, без подстановки материала другой задачи.
- UI Kit publication использует единый `SuitePrototype.connections()`; берёт UI Kit / Bitbucket, привязанные к проекту. API `settings('Подключения')` доступен из пустого назначения. `suite:connections-changed` обновляет readback, но не меняет зафиксированную цель ревью.
- При создании ревью фиксируются project, connection ID/name/address, repo, package и channel. Ready/return-for-changes сохраняют именно эту цель в истории. Изменившийся адрес или исчезнувшая привязка блокируют отметку ready и требуют заново выбрать назначение, а не перенаправляют операцию молча.

Проверено после этих правок: `node --check` и отсутствие whitespace errors. Перепроверка браузером: основной агент.

## Полный browser workflow · 13 октября 2026

Расширение `suite-prototype-browser-tools.js` / `.css` подключено перед основным модулем. Browser menu и звезда у адреса используют один controller; общие настройки приложения открывают те же browser settings. `SuiteBrowserTools.create(api)` получает состояние проекта, текущую вкладку, сохранение, отрисовку, диалоги и подготовку поручения. Это интерактивная демонстрация: нет реальных страниц, секретов, DevTools/CDP или очистки Chromium.

- Встроенный inspector: Elements, Console, Sources, Network, Storage, Performance. Breakpoints, pause/step/watch, ограниченные команды Console, фильтры, request details, offline/throttling, preserve log, запись fixture-профиля. Resize мышью/клавиатурой, expand/restore, F12 и Ctrl/Cmd Shift I в браузере; вкладки инспектора имеют отдельный keyboard routing.
- Состояние отладчика раздельно по tab ID + browser profile. Видимость общей области инспектора относится к рабочей панели; переходы не меняют активную вкладку браузера.
- Звезда: add/edit bookmark, folder, поиск, удаление, JSON import/export с проверкой URL/размера/дубликатов. Ctrl/Cmd D при фокусе браузера. Импорт HTML остаётся будущей реализацией; текущий UI явно называет JSON. Существующие bookmarks переносятся в новый проектный каталог.
- Cookies, local/session storage, HTTP cache, IndexedDB, service workers: демонстрационные записи по профилю и origin, отдельные категории очистки, scope текущий сайт/профиль. Незнакомый URL показывает собственное пустое состояние. Реальная domain-гранулярность описана в BROWSER.md, не выводится из fixture.
- Пароли: настройки предложений, демонстрация save/update/never/autofill. Только тестовые метаданные; секрет не создаётся и не вводится. Autofill недоступен вне точного fixture-origin, другой профиль не видит записи.
- Настройки запуска/загрузок/third-party cookies сохраняются как параметры макета; отсутствие сетевого движка указано рядом. Engine behavior и Windows vault проверяются после согласования по BRW-09…12.

Live UI: добавление/поиск/звезда/reload bookmark; breakpoint, pause/step, Console `2 + 2`, Network Offline, Performance start/stop; очистка HTTP cache 3.2 → 0 МБ сохранила две cookies, IndexedDB 1.4 МБ и соседний cache 8.1 МБ; save/update/autofill metadata, отказ на чужом origin, пустой vault другого профиля; tab mode restore; resize 300 → 348 px, expand/restore и F12 close/open. Светлая тема при 768×1000 и естественный размер тёмной темы, журнал без JS errors.

Node VM audit: `review-evidence/browser-tools-audit.cjs` и JSON рядом. Это проверки extracted module/callbacks с заменителями DOM, не доказательство движка. В коде обнаружено и исправлено уничтожение inspector DOM вызовом highlighter на контейнере; теперь подсвечиваются только отдельные code/pre. Production `app/` не менялся.
