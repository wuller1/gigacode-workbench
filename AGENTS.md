# Работа над GigaCode Workbench

Это личный инструмент пользователя, не производственная система. Продвигайся небольшими работающими срезами; проверяй реальный результат и предлагай улучшения, не меняя молча цель задачи. Не переноси облегчённые правила этого репозитория на производственные проекты пользователя.

## Начало работы

Если агент запущен на рабочем Windows для первичного переноса, начни с `WORK-COMPUTER-BOOTSTRAP.md` и сохрани продолжение до перезапуска GigaCode.

1. Прочитай `README.md` и `docs/IMPLEMENTATION_STATUS.md`. Они отделяют реально работающий `app/` от целевых контрактов.
2. Для полного расширения Browser/Design/IDE/Tasks/Operations/Sprut/Data/Review и agent runtime начни с `SUITE-UPGRADE-AGENT.md`, затем возьми одну карточку из `suite/implementation-plan.json`. Для прежних workflows используй `workbench/START-GIGACODE-UI.md`. Не загружай весь пакет в контекст.
3. На рабочем Windows сначала проверь сборку и установленный GigaCode **26.10.6** по `docs/MANUAL_ACP_PROBE.md`. 26.9.75 встречается только как исторический baseline. Начни с бесплатных initialize/new/config проверок. Не считай совместимость Qwen доказательством совместимости форка.
4. Если требуется собственный CLI внутри дистрибутива, следуй `docs/BUNDLED_CLI.md`. Не копируй настройки авторизации и историю вместе с runtime. Не меняй исходники чужого CLI.
5. После проверки окружения продолжи ближайшую готовую карточку из `suite/implementation-plan.json`, сверив её с фактическим кодом и `docs/IMPLEMENTATION_STATUS.md`. Если пользователь уже поручил этот срез, выполняй его без повторного согласования.

## Правила реализации

**Текущий этап — реализация.** 14.10.2026 пользователь прямо поручил: «Реализуй максимум функционала, не останавливайся на промежуточные результаты… я тебе разрешаю любые правки». Это снимает прежний запрет на runtime-разработку и разрешает улучшение UI/UX без повторного согласования макета. Требования, evidence-first миграция, проверки и честное разделение реализованного/непроверенного сохраняются. Актуальный объём IDE: `docs/suite/IDE-ULTIMATE-RESEARCH.md` и `suite/ide-ultimate-parity.json`.

- Иерархия: проект → задача → разговоры/роли/исполнители. Не создавай второй несвязанный workflow-контроллер рядом с текущим состоянием.
- Основной UX — чат, компактные инструменты, настоящие материалы, перестраиваемый план и перетаскиваемые панели. Вопросы показываются поверх рабочей области. Скрытая координация не превращается в ленту уведомлений.
- Приоритет дизайна — desktop: мышь, клавиатура, компактные панели, несколько инструментов одновременно. Сначала проверяй обычное настольное рабочее место; адаптация узкой панели сохраняет desktop-поведение, а не превращает продукт в мобильный интерфейс. Не скрывай частые действия ради мобильной композиции.
- Для IDE основной ориентир пользователя — IntelliJ IDEA: поведение editor groups, Project tree, Git, Run/Test/Debug и tool windows. Саму IDEA/GigaCode IDE в Workbench не встраивать; текущая самостоятельная реализация использует Theia. На работе доступен GigaCode IDE, форк Community, с неизвестной здесь версией и набором plugins. Его наличие не подтверждает Ultimate-функции и не требует companion plugin. Сравнивай уже написанную оболочку по фактам, сохраняя более удачные решения.
- Источники истины: реальные ответы CLI и его capabilities/config, файлы, наблюдаемый UI, тесты. Неподдерживаемую возможность обозначай явно. Не подменяй настоящий backend демонстрационными данными.
- Ролевые инструкции собираются как CORE + одна роль с source hashes/fingerprint; SYSTEM_PROMPT — legacy entrypoint. Точный allowlisted Qwen 0.25.1 получает source-verified append, неизвестный GigaCode 26.10.6 — явно обозначенный context-only до отдельной проверки. Source/ACP startup не доказывают полный provider request или model obedience. Не заменяй native CLI base и не меняй глобальный system env/file между исполнителями.
- Сохраняй workplace LLM-router и подключай его через WorkbenchOptions.routeProfile; ручного каталога ролей не нужно. Retained fallback неизвестного CLI не считается готовой автоматической маршрутизацией. При миграции сравни существующую реализацию по фактам и сохрани удачное; дополнительные шаблоны не навязывай импортом.
- Не повторяй весь prompt после неизвестного исхода: сначала сверка внешних эффектов, затем восстановление. Встроенные повторы провайдера и host retries — разные уровни.
- Для переходов одной задачи и восстановления прочитай `docs/suite/RUNTIME-TRANSITIONS-RESILIENCE.md` и адресно `workbench/docs/IN_TASK_ROLE_TRANSITIONS.md`. Переноси service/types/MCP/main/UI contracts совместно. Не запускай нужный следующей роли сервер как обычный background child CLI; используй фактические host IDE Task/Debug tools, проверь running/готовность и ownership. После fatal stop разрешены только чтение/диагностика/завершение и явный restart, UNKNOWN не повторяется.
- Храни короткий checkpoint, ссылки на факты и результаты проверок. Для длинного контекста используй адресное чтение истории/документов. Память — проверяемые сведения, не источник разрешений.
- Уважай чужие несохранённые изменения. Не перезаписывай файлы после конфликта сохранения. Не отключай TLS-проверку для корпоративных сертификатов.
- До завершения проверь импорт/сборку, подходящие тесты и затронутый живой сценарий. Текст модели «всё работает» не считается проверкой. Различай unit, protocol fixture, live CLI, live Electron и Windows installer.

## Команды и выдача результата

Из `app/`: `npm ci --include=optional`, `npm test`, `npm run build`, `npm start`. Из корня: `node tools/check-bundle.mjs`. Windows CI дополнительно запускает прежние PowerShell-тесты под Windows PowerShell 5.1 и собирает NSIS/portable.

Не запускай платные live prompts по умолчанию. Их отдельная команда и явный переключатель описаны в manual probe. Не выводи ключи или полный environment. `app/runtime/package`, локальные данные, трассы и `node_modules` не публикуются в Git.

Для каждого среза выдай работающий результат, короткий список наблюдений, способ повторить проверку и оставшиеся ограничения. Обнови статус документации только по фактам. Следуй зависимостям `suite/implementation-plan.json`: не переставляй карточки по пересказу из другого документа и не закрывай final audit до terminal dependencies.
