# Машинные данные плана

Этот каталог помогает слабой модели выполнять полный upgrade по одной карточке и восстанавливаться после обрыва.

- `implementation-plan.json` — зависимости, статус, outcome, acceptance и evidence каждой карточки.
- `migration-inventory.example.json` — шаблон аудита уже написанного кода и реальных connections.
- `checkpoint.example.json` — минимальный проверяемый контекст активной карточки.

Рабочий агент создаёт локальные копии inventory/checkpoint в своём task journal или userData. Файлы с корпоративными endpoints, schemas, путями, логами и credential refs не коммитятся без проверки. В репозиторий возвращаются только очищенные решения, универсальные contracts и evidence публичных fixtures.

## Обновление карточки

1. Проверить `dependsOn` и actual code; `planned` не означает отсутствие чужой реализации.
2. Зафиксировать исходный commit/dirty files и acceptance IDs.
3. Заполнить checkpoint до первой мутации.
4. После каждого значимого шага обновить `completedSteps`, `touchedOwners`, tests и один `nextStep`.
5. `verified` ставится только после всех требуемых уровней проверки; документ/макет не является evidence backend.
6. При внешнем блокере сохранить точную попытку, ответ/корреляцию без секретов и независимые шаги, которые уже завершены.

Не хранить весь transcript. Сохранять факты, решения, ссылки, hashes и короткое резюме, достаточное для продолжения.
