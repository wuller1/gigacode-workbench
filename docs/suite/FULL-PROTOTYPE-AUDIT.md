## Единая рабочая строка панелей · 14 октября 2026

По замечанию пользователя убрана отдельная строка заголовка (37 px) во всех девяти панелях: чат, IDE, браузер, браузер агента, задачи, дизайн/материалы, Operations, БД и Review. Закрытие, разворот и расположение встроены справа в первую рабочую строку инструмента. Точечная ручка поддерживает перетаскивание и открывает меню расположения по нажатию; свободное место строки также перетаскивается. Интерактивные элементы не запускают drag. Контекстное обращение к агенту сохранено без дублирования существующих команд инструмента.

Рабочие действия при нехватке места прокручиваются отдельно; close/restore остаются на месте. Групповые вкладки занимают собственные 32 px и не перекрывают toolbar. Перерисовка инструмента переносит те же управляющие DOM-узлы обратно в новую рабочую строку. В IDE исправлены поиск toolbar и CSS скрытых кнопок после обёртки: переключение Editor/Git сохраняется.

Живая проверка на 983×924: все девять панелей получили по одной группе управления без отдельного header; открытие таблицы, смена вкладки браузера, IDE↔Git, список задач, материалы, Jenkins и Pull requests не теряют контролы. Перенос БД мышью поменял панели местами и вернул обратно; меню после drag работает с первого нажатия. Проверены разворот/восстановление, закрытие инструментов, независимая группа вкладок и светлая/тёмная темы. Ошибок JavaScript в проверенном сценарии не обнаружено. Это проверка макета, не Electron runtime.

Доказательства: `workspace-layout-audit.json` (33 проверки), `workspace-chrome-audit.json` (8, включая negative control прежнего IDE селектора), regression IDE UX (12), IDE Git (46), DB (55). Снимки: `panels-integrated-data-dark.png`, `panels-integrated-light.png` в `design/review-evidence/`.

## Итерации критики и исправлений

1. **Полнота путей.** Добавлены подробные модули IDE/Data, Tracker/Forge/Operations/Knowledge и Browser/Design. Основные действия ведут в формы, просмотр результата или понятное ограничение демонстрации. Макет отделён от прежних runtime-изменений. Проводник файлов удалён из общей навигации: он находится только внутри IDE, слева, открыт по умолчанию и скрывается отдельной кнопкой.
2. **Владение состоянием.** Исправлены смешение истории разных проектов, сброс редактора от завершения агентского хода, потеря адресного ввода, перезапись черновика при передаче контекста из панели. Модель/reasoning, очередь и вопросы принадлежат разговору; терминалы — проекту. Смена проекта и переименование сохраняют соответствующие банки данных.
3. **Общие подключения.** Settings и рабочие панели используют один реестр с привязками к проектам. Новый адрес показывает пустое состояние без чужого каталога. Операции фиксируют исходную цель; её изменение или отвязка требуют явного разрешения конфликта. Смена адреса/типа исходного подключения снимает демонстрационный адаптер.
4. **Навигация и выход.** Добавлено закрытие инструментальной панели с возвратом широкого чата, повторное нажатие активного инструмента, сохранено меню браузерной панели. Командная навигация не открывается поверх незакрытого редактора-диалога. Вложения, вопросы и настройки имеют Escape/закрытие; вопрос сохраняет черновик без отправки. Исправлены подписи полей и положение кнопок окна на узком экране.
5. **Повторная проверка.** Отдельные аудиторы искали ошибки переходов и состояния; основной агент проходил сценарии через видимый UI. Найденный сбой формы PR при approve исправлен и повторно проверен. Дополнительная проверка IDE обнаружила зависимость последней вкладки от удалённого README; исправление вводит пустое состояние редактора вместо обращения к отсутствующему файлу.
6. **Детальные профессиональные экраны.** Добавлены граф истории и blame, интерактивный план rebase с валидацией, повторное review нового PR head, эпики и аналитика спринта. Контекст открывается из Send правой кнопкой или Shift+F10. Продолжение с checkpoint создаёт отдельный разговор, сохраняя исходную историю; неизвестный результат блокирует продолжение до сверки. Верхняя общая кнопка ведёт в подключения проекта, а конкретный стенд показывается в рабочем инструменте, чтобы не выдавать декоративный общий переключатель за реальное изменение цели.

## Статические проверки и границы доказательств

### Дополнение Service Mesh · 13.10.2026

По запросу пользователя добавлены EnvoyFilter и DestinationRule в OpenShift / K8s → Service Mesh, а в план S6-03/S6-04/S6-11 — критерий KUX-03. Независимая проверка уточнила клиентский selector DestinationRule, targetRefs EnvoyFilter и запрет смены identity из YAML. В предпросмотр добавлена отдельная область действия; удаление больше не обращается к последней записи списка, если исходного объекта уже нет.

Через живой UI макета проверены:

- Оба типа в OpenShift («Корпоративный кластер») и Kubernetes («Sandbox»), переключение ДЕВ/ИФТ и возврат к исходному подключению.
- DestinationRule: изменение maxConnections 80 → 120, дополнительный exportTo из YAML, переход через форму без потери поля, diff, apply и отображение rv2. Изменение namespace блокируется с объяснением.
- EnvoyFilter: ошибка JSON selector, явная широкая область без selector, конфликт версии 409 без сохранения. В финальной версии — создание отдельного тестового фильтра, видимая область в preview, apply и удаление только созданного объекта.
- Отдельные состояния CRD missing, Forbidden read и readonly; readonly отключает edit/delete/create, сохраняя просмотр. Состояния Sandbox не перенеслись в OpenShift.
- После финальной загрузки новых ошибок JavaScript в журнале нет. Кластеры и MCP не подключались; схема Istio, реальный dry-run, влияние на proxy и полная YAML-совместимость этим не доказаны.

- Пять подключённых JS-модулей проходят `node --check`; inline-скрипты точки входа проверены на разбор. `git diff --check` не сообщает ошибок пробелов.
- Раздел suite в `tools/check-bundle.mjs`: `ok=true`, проверены 68 карточек плана, 200 критериев, 14 ролей, 29 workflows и 33 файла UI kit. Эти числа относятся к структуре пакета, не к выполнению всех сценариев UI.
- Общая проверка пакета пока не зелёная: прежний manifest обвязки содержит устаревшие хеши/инвентарь. Он не переписан лишь ради зелёного статуса, новая публикация или релиз не выполнялись.
- Сверка SHA-256 с сохранённым начальным состоянием 660 файлов `app/` не выявила изменений этого этапа. Существовавшие ранее незакоммиченные изменения не откатывались.
- В журнале браузера остаётся ранняя ошибка `showPR` до исправления; она не скрывается и не считается новым сбоем финальной версии. После исправления approve проверен повторно.

### Очередь сообщений · 13.10.2026

Очередь перенесена из всплывающего окна в компактный блок над composer. У каждой строки — «Сейчас», карандаш и корзина. Правка выполняется внутри строки; Ctrl/Cmd+Enter сохраняет, Escape отменяет. Короткая панель ограничивает высоту списка, чтобы оставить место истории; список прокручивается отдельно. Пустая очередь скрыта.

Исправлены отправка старого текста во время редактирования, повторный claim уже отправленного item, потеря получателя в отложенном действии и устаревшие обработчики после повторного открытия редактора. Edit hold удерживает автоматическую FIFO, но не текущий ход. Явная отправка другого item сохраняет hold. После Stop обычный ввод пополняет удержанную очередь; «Сейчас» явно начинает новый ход. Подсказка отражает это различие.

Выборочно пройдено в живом UI макета: три сообщения на паузе, удаление одной строки, отмена правки через Escape, запрет пустого Save, сохранение Ctrl/Cmd+Enter; завершение хода при открытом редакторе без отправки старого текста; отправка другого item с паузы; Stop → edit/save без автозапуска → «Сейчас»; новый разговор с пустой очередью и возврат к сохранённому edit draft; сворачивание/раскрытие очереди. Проверены полная ширина и узкий чат рядом с браузером, обе темы; в окне 768×1000 горизонтального переполнения очереди/страницы нет. У действий доступные имена, размер целей не меньше 30×30 px. В финальной загрузке новых JS errors не зафиксировано.

Отдельная проверка фактических функций с управляемыми таймерами: **18/18**; отчёт [queue-state-audit.json](../../design/review-evidence/queue-state-audit.json). Это проверка демонстрационного состояния с минимальным DOM, не доказательство live ACP, restart, multi-window host или реальной доставки. Скриншоты: [очередь](../../design/review-evidence/message-queue.png), [правка](../../design/review-evidence/message-queue-edit.png). Синтаксис shell и inline JavaScript проверен. SHA-256 711 файлов app совпал с исходным состоянием предыдущего этапа; runtime не менялся.

Переименование файлов не выдаётся за семантическое переименование классов или импортов. Семантическая работа с Java/Python требует соответствующего adapter.

Каталог расширений содержит проверенные Open VSX IDs и metadata licenses, поиск/детали/план установки/JSON settings и корпоративный registry URL. «В плане» не означает download/install/activation. Полноценный extension host выбирается по новой **S4-00 planned** до IDE platform implementation; сохранены все последующие S4 acceptance и runtime gate. Выбор Theia/Code-OSS/Monaco compatibility — сравнительный эксперимент на Windows, а не уже выполненная миграция.

Независимые проверки настоящих функций в VM: **34/34** language/Spring/Maven, **26/26** explorer, **10/10** extension dialog ownership. Отдельные регрессии: **45/45** Git и **33/33** syntax core. Исправлены устаревшие callback после cancel/restart, неверный owner у фонового завершения, ошибочный переход debugger на активный файл, старые зелёные результаты после edit, cross-project callbacks старой модалки extensions, повторный Undo как скрытый Redo и повторное раскрытие compact-folder после rerender.

Живые проверки: Java import → test failure → fix preview → dirty/stale result → rerun; debug сохраняет исходный target после выбора TypeScript-вкладки; Python выводит свой pytest failure; frontend Vite/preview меняет состояние кнопки; массовое переименование двух Java-файлов обновляет вкладку и отменяется; скрытая цепочка каталогов остаётся закрытой после другого действия; поиск/терминальный draft и focus переживают async completion; подсветка остаётся после переиспользования редактора. Высота нижней панели изменяется клавиатурой; при 1280×720 root clientHeight=scrollHeight, нижняя строка полностью видна. Светлая тема проверена на том же viewport. Попытка browser-wide viewport override не изменила скрытую тестовую вкладку: снимок не выдаётся за 768 px проверку, override сброшен.

Скриншоты: [Java IDE](../../design/review-evidence/ide-java-workspace.png), [светлая тема](../../design/review-evidence/ide-java-light.png), [каталог расширений](../../design/review-evidence/ide-extension-catalog.png). Настоящие LSP/DAP, Java/Python/Node processes, Windows, framework intelligence и установка расширений не проверялись и остаются pending. 711 контрольных файлов `app/` не менялись. Общий bundle checker по-прежнему выявляет старые расхождения legacy manifest и существующие ограничения распознавания acceptance/motion markers; этот проход не является готовым релизным архивом.


### Браузерные файлы и Git-цвета · 13.10.2026

Единый компонент загрузок подключён к личному и агентскому браузеру, с отдельными holder/owner IDs. Локальные примеры проверяют progress, pause/cancel/retry, text preview/edit/diff, original/revisions/draft, export и явный переход в IDE. Переименование проекта сохраняет ID/версии/черновик; обновление выполняется после стабилизации scope. Старые callback/таймеры не меняют новое окно. Ошибка persistence не маскируется успешным сохранением. IDE импорт повторно открывает ту же копию без перезаписи dirty/saved edits; rename/Undo обновляет import path.

Независимый VM audit: **44/44** ([сценарии](../../design/review-evidence/browser-downloads-audit.cjs), [отчёт](../../design/review-evidence/browser-downloads-audit.json)). Регрессии: explorer **26/26**, language **34/34**, agent browser **30/30**, browser tools **16/16**, Git **45/45**. Старый explorer harness требовал обновить instrumentation marker после расширения API; после обновления все прежние сценарии прошли. Это проверки фактических функций макета, не network/Windows evidence.

Live UI: JSON download fixture → edit/diff/save → IDE; повторное открытие сохраняет изменённый IDE buffer; dirty close → reopen восстанавливает черновик; большая CSV fixture показывает только фрагмент и отключает недопустимые edit/export. Ошибок JS не обнаружено. Source и diff подсвечиваются существующим syntax renderer. [Сравнение файла](../../design/review-evidence/browser-download-edit.png).

Имена в проводнике используют общий Git snapshot: blue modified, green added, brown untracked, teal renamed, olive ignored, red conflicts/deleted; tooltip/marker доступны независимо от цвета. Dirty-buffer отдельно, unknown не выдается за clean. Проверены dark/light и сохранение цвета выбранного файла. [Тёмная тема](../../design/review-evidence/ide-git-file-colors.png), [светлая тема](../../design/review-evidence/ide-git-file-colors-light.png).

Реальные загрузки, native файл/DocumentService и произвольное редактирование документов не реализованы. PDF в макете — metadata-only, «2 ГБ» — bounded fixture, а не настоящий transfer. Контракт BROWSER-FILES и карточка S2-05 описывают интеграцию; final audit зависит от неё. Production app в этом срезе не менялся.

### Единообразное размещение панелей · 14.10.2026

Устранена причина «сплит не сработал»: render автоматически сворачивал разбиения во вкладки при нехватке размеров, а центр менял панели местами. Теперь `leaf/group/split` — отдельные сохранённые состояния; края создают сплит, центр объединяет вкладки. Одни правила действуют для ручки, вкладки и значка rail, включая закрытую панель и отделение из собственной группы. Размеры, открытие терминала и reload не меняют тип размещения. Старые свёрнутые группы мигрируются один раз; reset сохраняет version 2.

Обычный щелчок по новому инструменту добавляет вкладку в активную инструментальную группу, без эвристики ширины. «Открыть все» даёт чат и одну группу инструментов. Меню размещения/overflow группы немодальные и поддерживают Escape/outside close без перехвата фокуса другого редактора. [Актуальный контракт](WORKSPACE-PANEL-LAYOUT.md) заменяет ранние правила этой страницы о полосе чата, центре-обмене и адаптивных группах.

Проверки: layout **46/46**, chrome **8/8**, actual UI: все четыре края, центр, drag tab/handle/rail, смешанный horizontal/vertical split, сохранение при открытии терминала, resize и reload. JS errors в проверенной тестовой вкладке не зарегистрированы. Макет остаётся согласуемым; app/ не менялся.

Дополнительно в пользовательском окне 983×924 оставлена раскладка: чат слева, IDE и браузер справа друг над другом, остальные инструменты вкладками с IDE. Выбранная вкладка автоматически удерживается в видимой части списка, toolbar не переносится в несколько рядов. [Снимок](../../design/review-evidence/workspace-explicit-docking.png).
