# Рабочая IDE: установка, перенос и проверка

14 октября 2026. Реализация разрешена пользователем. Это инструкция по существующему коду `app/` + `ide/`; целевой объём Ultimate описан отдельно в [матрице](IDE-ULTIMATE-PARITY.md). Наличие расширения не означает прохождение всех сценариев матрицы.

## Что переносить

- `ide/`: закреплённый Theia 1.76.0, собственный bridge, темы, источники/хеши VSIX, Node и Java/Maven, установщики и реальные Java/Python fixtures.
- `app/electron/ide-process.ts`: независимые backend-процессы по реальному корню проекта; отдельные конфигурации и журналы. Один корень с несколькими alias не создаёт дубликаты.
- `app/electron/ide.ts`: sandboxed WebContentsView, локальная аутентификация HTTP/WebSocket, жизненный цикл, перенос между окнами, scoped RPC.
- `app/src/IdePanel.tsx`, `IdeSettings.tsx`: нативная поверхность IDE, ошибки подключения, настройка и диагностика движка.
- `app/src/docking.ts`, `Workspace.tsx`: единое дерево split/group, перетаскивание к четырём краям/в центр, вкладки, закрытие, разворачивание, клавиатурный resize, сохранение расположения. Чат скрывается и возвращается одной кнопкой слева над IDE.
- `app/electron/mcp.ts`: инструменты `ide_*`; `service.ts`: правила работы с ними. Используй регистрацию текущей сессии, не создавай обходной неограниченный MCP-сервер.
- `app/src/ModelPicker.tsx`, `QueueMessages.tsx`, `motion.ts`: компактная модель/reasoning, цветное кольцо контекста, inline очередь и индикатор работы для ВАРМ. Переноси вместе с backend `queue.sendNow` и optional полями `Message.elapsedMs/outcome`.

Theia владеет моделями открытых документов. Агент читает и редактирует те же несохранённые buffers. Второй редактор с собственным изменяемым состоянием поверх них недопустим. Нельзя подменить семантическое переименование поиском строк. Открытие native preview — состояние pending, а не применённая правка. Перед агентским run/test/debug нужные file buffers должны быть явно сохранены; не сохраняй посторонние изменения, чтобы пройти эту проверку.

## Установка из исходников на Windows

В каталоге `app`, в обычном Windows PowerShell 5.1:

```powershell
npm.cmd ci --include=optional
npm.cmd run setup:ide
npm.cmd test
npm.cmd run build
npm.cmd run test:ide
npm.cmd start
```

`setup:ide` скачивает проверенный официальный Node 22.23.3 в `app/runtime/ide-node`, устанавливает закреплённые npm-пакеты IDE, распаковывает VSIX из lock, готовит Temurin Java 21 и Maven 3, собирает bridge/frontend/backend. Глобальные настройки Node/JDK/PATH не меняются. Для языкового прогона дополнительно нужен установленный Python с venv:

```powershell
node tools/test-ide-live.mjs --languages
```

Обычный прогон не использует провайдера моделей, токены или пользовательский CLI. `--languages` проверяет настоящие Pyright/JDT, Python/Maven/JUnit и нативные test controllers; для первого импорта Maven нужны доступные зависимости. Proxy/CA/mirrors настрой штатно для каждого runtime. Не отключай проверку TLS. `--offline` у setup использует npm cache; VSIX, Node и SDK также должны быть заранее закэшированы. Полностью пустой компьютер без сети этим флагом не обеспечивается.

Не путай JDK языкового сервера и JDK проекта. Укажи нужные Java runtimes, Python interpreter/venv и Maven/Gradle wrappers в нативных настройках IDE. На Windows выбираются `win32-x64` debugpy/Ruff и Windows SDK; macOS-архивы туда не копируются.

## Интеграция в уже доработанную оболочку

1. Сохрани текущий Git diff и рабочую резервную копию. Выпиши существующие реализации editor/document authority, LSP/DAP, тестов, docking, Git и extension host с доказательствами.
2. Сравни поведение на одних fixtures, а не число кнопок. Если существующий вариант лучше, сохрани его; аргументируй различие. Если объединить варианты без потерь нельзя, покажи пользователю конкретный выбор согласно `SUITE-UPGRADE-AGENT.md`.
3. Переноси сервисами с сохранением текущих Project/Task/Session identity, CLI/ACP, памяти, авторизации и MCP-подключений. Не подменяй установленные GigaCode credentials и не патчь CLI.
4. Собери реальный IDE runtime. Отдельно проверь extensions activation, язык документа, диагностическую ошибку и её исправление. Текст «плагин установлен» не является проверкой.
5. Пройди операции read → expectedVersion + expectedRevision edit → повтор operationId → stale rejection → save → disk/Git readback; semantic rename → просмотр всех файлов → apply → сборка/тесты. Не делай regex rename вместо language provider.
6. Проверь задачи с exit 0 и ненулевым exit, тесты с найденными/завершёнными test cases, DAP с действительным stopped stack, перезапуск с dirty buffer, внешнее изменение диска, переключение проектов/окон и сохранение tabs/layout.
7. Только после этого перенеси статус подтверждённых сценариев в capability manifest. Остальные acceptance units остаются открытыми.

## Восстановление и отказоустойчивость

Несохранённые file buffers сохраняются вне репозитория в конфигурации IDE. Идентификаторы terminal processes привязаны к backend epoch. После его замены восстанавливаются свежие интерактивные shells, завершённые task commands не исполняются повторно.

Обычный ввод записывается с debounce 100 мс; агентская правка ожидает durable receipt. Операция сначала записывает pending receipt, затем результат. Если после сбоя остался pending, возвращается `OPERATION_OUTCOME_UNKNOWN`: сверить файл и buffer, не повторять эффект.

Ревизия документа включает lifetime редактора, поэтому совпавший номер Monaco version после перезапуска не принимает старую правку. Раскладка самой Theia также хранится на диске по проекту, независимо от временного HTTP-порта.

При следующем запуске черновик восстанавливается как dirty buffer только если диск совпадает с исходной базой. Изменённый/удалённый на диске файл не перезаписывается. Команда `Workbench: восстановление несохранённых файлов` открывает сохранённый текст и сравнение; копию можно сохранить штатно. Черновики содержат исходный код, поэтому не включай локальную конфигурацию IDE в публичные архивы/диагностику.

Лимиты: до 2 млн символов на автосохраняемый черновик, 18 млн суммарно; при превышении или ошибке записи видна ошибка. Последние 100 мс обычного ввода при аварийном завершении/отключении питания не гарантируются. У штатного restart сначала flush; сбой persistence не должен молча уничтожать редактируемый buffer.

Один корень имеет одну живую авторитетную поверхность IDE, которую можно перенести в другое окно. Чаты и процессы других проектов продолжаются. Одновременное независимое редактирование одного dirty buffer в двух нативных окнах не объявляется реализованным.

## Сборка дистрибутива

```powershell
npm.cmd run prepare:ide-package
npm.cmd run dist:win
```

Staging исключает download caches, личные настройки и историю; включает независимый Node, собранную Theia, platform modules, VSIX, JDK/Maven, corresponding-source архив JDK и лицензии. Упаковку делать на целевой ОС. Текущий локальный прогон macOS не подтверждает Windows installer, корпоративный ВАРМ, сертификаты, внутренние MCP или GigaCode 26.9.75. Для них есть Windows workflow и рабочий probe.

Каталог расширений — Open VSX и разрешённые VSIX. Microsoft Marketplace и закрытые Ultimate-компоненты не копируются. Сохраняй исходные лицензии/NOTICE и corresponding-source сведения JDK из lock; собственная лицензия репозитория не заменяет лицензии зависимостей.

## Перенос панели ввода и очереди

Сохрани текущий backend очереди, если он уже обеспечивает более сильные гарантии. Наш вариант использует одну атомарную запись для приоритета и остановки допуска, один prompt на ACP connection, ожидание исходного terminal response и ручную сверку unknown. Явный Stop отменяет ранее запрошенное автоматическое продолжение. После перезапуска приложения оно не восстанавливается без решения пользователя. Не меняй этот механизм на повтор отправки по таймеру.

`Message.elapsedMs/outcome` записываются backend после фактического terminal response. «Выполнено за…» показывается только для completed; cancelled/unknown имеют собственный статус. Историческим сообщениям время не придумывается.

Модель и reasoning находятся в одном popup. Используй только configOptions текущего CLI и readback. Профиль выбирается автоматически. При недостатке места сначала скрывается ветка, сокращается название модели, reasoning остаётся отдельным фрагментом. Кольцо показывает usage; неизвестные данные не превращаются в фиктивные 0%.

`npm.cmd test` и `npm.cmd run test:ui` не используют токены. Native IDE использует резервный frame clock: Windows может остановить requestAnimationFrame у скрытой WebContentsView даже при backgroundThrottling=false. Host status использует один JS clock только при наличии индикаторов. Системное отключение CSS-анимаций не делает работу невидимой; явная настройка уменьшения движения внутри приложения сохраняется. Реальный ВАРМ проверяется отдельно.
