# Как проверить полный макет

Новый маршрут: откройте чат, браузер и IDE; проверьте вкладки группы при нехватке места, перенос мышью, поиск из свёрнутой нижней панели. Передайте задачу или код агенту, откройте компактное вложение, переключите разговор и вернитесь. Черновик и вложение должны сохраниться. [Полный отчёт критики](UX-AUDIT-2026-10-13.md).

Откройте `design/suite-workspace-prototype.html` через локальный сервер проекта. Текущий просмотр: `http://127.0.0.1:50515/design/suite-workspace-prototype.html`. Внешние инструменты макета используют демонстрационные данные. CLI, Git-команды, SQL, Jenkins и кластеры не запускаются.

Сначала проверьте удобство обычной работы, затем формы и сложные состояния. Статус согласования остаётся `design_in_progress`. Этот файл не разрешает начинать реализацию.

## Основная компоновка

1. Справа откройте **Code / IDE**. Проводник слева внутри IDE, изначально открыт. Кнопка панели рядом с Code скрывает и возвращает его. Выбранный файл и введённый текст должны сохраниться.
2. Кнопка сверху слева скрывает и возвращает чат в одном и том же месте. Выбор разговора находится в заголовке чата.
3. Перетащите заголовок чата/инструмента, чтобы поменять стороны. Разделитель регулирует ширину. X в заголовке инструмента возвращает широкий чат; повторное нажатие активной кнопки справа тоже закрывает инструмент.
4. Переключите проект сверху. Затем вернитесь: активная вкладка браузера, файлы IDE и черновик разговора относятся к своим владельцам.
5. Проверьте светлую тему и узкое окно. Модель + reasoning должны оставаться читаемыми; при недостатке места ветка скрывается первой.

Терминал можно переносить за значок с точками к любому из четырёх краёв. Зоны размещения появляются во время переноса. Граница меняет размер; для клавиатуры доступны меню расположения, стрелки и Home на разделителе. Вкладки и введённая команда сохраняются. На узком экране панель временно возвращается вниз; выбранный край восстанавливается при расширении. Это компоновка одной панели макета, не перенос процессов между нативными окнами.

## IDE и браузер

- **IDE:** дерево → открыть/создать файл → изменить → переключить вкладку → сохранить. Закрытие изменённого файла предлагает выбор; закрытие последней вкладки показывает пустой редактор с созданием файла.
- **Поиск по проекту:** найти текст → заменить → проверить diff выбранных файлов → применить локально.
- **Refactor:** Extract method или Change signature → параметры → предпросмотр затронутых файлов → применить в макете. Это fixture, не настоящий анализатор языка.
- **Действия редактора → Языковые службы:** статус → настройки → индексирование → отмена/повтор; проверьте сценарий недоступной возможности.
- **Действия редактора → Профилировщик:** процесс/режим → запись → timeline/flame/hotspot → открыть строку кода. Данные демонстрационные.
- **Browser Lab:** откройте второй адрес, вернитесь в другой раздел, снова откройте браузер. Должна сохраниться выбранная вкладка, без создания ещё одной.
- В браузере проверьте адрес, назад/вперёд, закрытие/восстановление вкладки, размер/ориентацию/масштаб, снимки, диагностику, разворот и меню внешнего открытия. «Поручить агенту» показывает управление и демонстрацию курсора.

## Задачи, Git и review

- **Tasks:** список/доска → задача → описание, критерии, подзадачи, связи, комментарии и история → «Взять в работу». В чат передаётся описание задачи; сам запуск CLI не имитируется настоящим результатом.
- **Фильтры → Эпики проекта:** родитель → дочерняя задача → возврат. **Спринт → Аналитика спринта:** Burndown и Velocity, выбор дня/спринта.
- **Source Control & Review:** diff файла и блока → подготовка → сообщение коммита → commit/push в демонстрации. Изменения агента отделены от пользовательских.
- **История:** граф коммитов; **⋯:** blame и план rebase. Неверный первый squash должен блокировать продолжение с объяснением.
- **PR #184:** изменения → комментарий к строке → approve. Затем «Новый commit · демо»: прежнее одобрение сбрасывается, комментарий помечается устаревшим, новый head требует повторной проверки.

## Базы данных

- **Data:** выберите подключение ДЕВ/ИФТ → SQL → параметры → результат/план/история. Измените ячейку, проверьте diff и режим транзакции, затем apply/rollback.
- Откройте объекты БД, функцию или процедуру → изменение определения → сравнение до применения.
- **Импорт:** формат CSV/XLSX/SQL → параметры/сопоставление колонок → COPY-план → задание. Проверьте большой файл, отмену, ошибку и неизвестный исход. Размеры файлов — сценарии интерфейса, не тест производительности.
- **Экспорт:** формат CSV/XLSX/SQL, выбранные данные/параметры, задание и результат. Фактическая работа JDBC/COPY не проверяется HTML-макетом.
- **Действия с результатом → 5 000 строк:** переключение страниц, фильтры. Большой набор не должен превращаться в гигантский DOM.

## Корпоративные инструменты

- **Подключения** в верхней строке: один endpoint/auth reference → привязки к нескольким проектам. Добавьте примерный Jenkins; он должен появиться в списке и показывать пустое состояние без чужих данных. Не вводите настоящие секреты.
- **Operations → Jenkins:** контроллер → все пространства или ДЕВ/ИФТ → джоба → параметры → запуск → очередь → стадии/логи/тесты/артефакты. Для deploy есть Input с собственным комментарием. Переключение селектора не перенаправляет начатый запуск.
- **OpenShift / K8s:** connection → стенд → namespace → ресурс → YAML/diff, события, логи/exec, scale/rollout/rollback. Отдельно проверьте метрики, сеть, storage, RBAC, operators/CRD и cluster administration.
- **OpenShift / K8s → Service Mesh:** EnvoyFilter / DestinationRule → обзор области действия → YAML и правка → diff → применение в макете. Повторите для подключений «Корпоративный кластер» (OpenShift) и «Sandbox» (Kubernetes), затем для ДЕВ/ИФТ. Отдельно проверьте отсутствие CRD, отказ в чтении и режим только чтения; отсутствие ресурса не должно выглядеть как успешная пустая загрузка при отказе в доступе.
- **Документация:** подключение → пространство → страница → правка → внешний конфликт → сравнение/объединение → новая версия.

## Агент, материалы и восстановление

- В composer модель и reasoning выбираются вместе. Роль показывает решение агента; ручного выбора текущей роли нет.
- **Ход работы:** текущий шаг, выполненные шаги, исполнители, уточнение, пауза, остановка и предел повторов. Координационный журнал раскрывается отдельно.
- Отправьте сообщение, затем ещё два во время демонстрационного хода. Компактная очередь раскрыта прямо над composer, без popover: в каждой строке «Сейчас» (доступное имя «Отправить сейчас»), карандаш и корзина. Карандаш открывает inline-редактор с «Сохранить» / «Отмена»; Ctrl/Cmd+Enter сохраняет, Escape отменяет. Пока правка не сохранена или отменена, очередь этого разговора удерживается, даже если ход завершился. Обычная отправка в idle добавляется в хвост существующей FIFO-очереди, не обходит её голову.
- Проверьте Stop: остаток очереди сохраняется и сам не запускается. «Сейчас» — явное возобновление/новый демонстрационный ход для выбранного сообщения; для отправки редактируемого сообщения сначала нужно сохранить или отменить его правку. Явная отправка другого сообщения не снимает edit hold. Переключитесь между разговорами: очередь и черновик правки принадлежат исходному разговору. Проверьте двойной клик и одновременное завершение хода: стабильный ID сообщения и атомарный guard должны исключить повторную отправку.
- Очередь макета — только in-memory демонстрация. Эти шаги являются сценарием проверки, не свидетельством уже пройденного теста; live CLI, durable enqueue и восстановление после reload ими не доказаны.
- Вопросы открываются сверху по одному, со свободным ответом. Escape не отправляет ответ.
- Правый щелчок по Send или Shift+F10: контекст, сжатие, checkpoint, ошибки 429/413/400/HTML. При неизвестном результате повтор заблокирован до сверки.
- **Design & Artifacts:** brief → макет → состояния/размеры/темы → комментарии/версии → аудит → материал. Материал можно открыть, переименовать, править, экспортировать и архивировать.
- **UI Kit:** компоненты, варианты, токены и собственные иконки → назначение в корпоративном репозитории → локальное review публикации. Макет не публикует в Git.

Записывайте замечания через **Обзор макета → Записать замечание**, затем экспортируйте перед обновлением страницы. Итоги проверок и незакрытые специфические границы: [FULL-PROTOTYPE-AUDIT.md](FULL-PROTOTYPE-AUDIT.md).
## Проверка расширенной IDE · Java, Python, frontend

Откройте IDE слева и разверните панель. Проводник виден только здесь: строки по 23 px, компактные цепочки папок, поиск, Ctrl/Cmd+P, Ctrl/Cmd/Shift для выбора файлов, контекстное меню. Ширина дерева и высота нижней панели меняются мышью за границу или стрелками на сфокусированном разделителе. Проводник и нижняя панель скрываются отдельно.

1. В строке запуска выберите **Java → Среда**. Проверьте настройку JDK и импорт проекта. **Maven** открывает цели, build profile, offline, skipTests и зависимости; **Spring** — отдельный runtime profile, конфигурацию, beans/mappings и запуск Boot. Сведения из исходников отделены от live данных.
2. Запустите Java-тесты: исходный учебный `PaymentService` содержит дефект. Откройте упавшую проверку → предпросмотр → примените в буфер → повторите тесты. До повторного запуска старые результаты отмечены устаревшими. Поставьте breakpoint, запустите отладку и смените вкладку: Step остаётся связан с исходным Java-файлом.
3. Переключите стек на **Python**: настройте interpreter/pip/uv, подготовьте окружение и запустите pytest. В учебном примере показан дефект результата пустого `sum`. Есть Ruff, отдельный запуск скрипта, debug, watch и выражения из fixture-frame.
4. **Frontend**: выберите TypeScript, ESLint, Vitest, Playwright, build или Vite. У Vite после запуска появляется локальный preview с интерактивным состоянием кнопки. Произвольный сайт, Node-процесс и настоящий React build здесь не запускаются.
5. Выделите два файла → **Изменить**: задайте замену имени, префикс или папку → проверьте пути → примените. Конфликт имён блокирует применение. Отмена последнего переименования находится в меню проводника. Файловая операция не подменяет semantic rename/import edits.
6. Кнопка **Расширения IDE** в верхней строке открывает Open VSX-кандидатов, поиск, детали, лицензии, настройки проекта и корпоративный источник. **Добавить в план** создаёт намерение установить пакет после проверки движка. Статуса «установлено» в макете нет. VSIX и совместимость описаны прямо в этом окне.

Сценарии являются локальной демонстрацией, не проверкой реального проекта. Перед переносом следуйте [IDE-LANGUAGE-WORKFLOWS](IDE-LANGUAGE-WORKFLOWS.md), [IDE-EXTENSIONS-AND-EXPLORER](IDE-EXTENSIONS-AND-EXPLORER.md) и карточке S4-00. Существующие успешные решения пользователя не заменять без сравнительной проверки.


## Файлы из браузера и Git-цвета · 13.10.2026

1. Откройте «Браузер агента» → значок загрузки в строке вкладок. Для личного браузера: меню `…` → «Загрузки». Хранилища разделены.
2. «Тестовая загрузка» создаёт явно обозначенный локальный JSON; прогресс → открытие → «Редактор» → «Изменения» → «Сохранить версию». Оригинал остаётся доступен отдельно.
3. «В IDE» открывает независимую копию в `downloads/`. Измените буфер и повторите открытие той же версии — правки остаются. Переименование копии сохраняет эту связь. Native DocumentService ещё не подключён.
4. Закройте редактор с изменённым черновиком → «Сохранить черновик и выйти» → откройте файл снова. Текст восстановится. Проверьте PDF/большой файл: неполный контент не объявлен готовым для редактирования/экспорта.
5. В IDE имена `checkout.ts` / `retry-policy.ts` синие (`M`), тест зелёный (`A`) по общему Git fixture. Точка — отдельно несохранённый буфер. Неизвестный status нейтрален; это не утверждение clean. Значения и легенда доступны в настройках проводника.
