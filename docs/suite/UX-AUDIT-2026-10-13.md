# Критика и доработка макета · 13 октября 2026

Статус: `design_in_progress`. Проверен и изменён интерактивный HTML-прототип. Реальные Electron/MCP/CLI, SQL и внешние серверы этим проходом не проверены; согласование до runtime-разработки остаётся обязательным.

## Метод

Три независимых прохода по ролям: аналитик — целостность задачи и передаваемых фактов; разработчик — ежедневные переходы и сохранение работы; дизайнер — плотность, визуальная иерархия и полезная площадь. После первого списка замечаний внесены исправления, затем выполнена повторная критика на живом макете и проверка конкретных переходов. Третий общий проход проверил совмещение изменений. Наличие элементов на экране не считается доказательством работы будущего backend.

## Принятые изменения

| Наблюдение | Исправление и результат |
| --- | --- |
| Два открытых нижних блока оставляли редактору около 125 px высоты при 1280×720 | Терминал и IDE bottom свёрнуты по умолчанию; выбор пользователя сохраняется. Убран второй постоянный набор Problems/Tests из общей панели. Для кода остаётся около 320 px в проверенных раскладках |
| Третий инструмент сжимал IDE/браузер до нескольких строк | Недостаточно широкая/высокая группа отображается вкладками. Drag/resize и исходное разбиение сохраняются; при расширении восстанавливается split |
| Каждый заголовок повторял задачу, разговор и несколько агентских кнопок | Повтор убран, видна одна контекстная команда; смена разговора доступна в меню панели |
| Переключатели проектов/разговоров были крупными карточками с набором кнопок | Компактная строка открывает объект; вторичные действия — через ⋯. Поиск есть у проектов, задач и разговоров; пустой результат объяснён |
| Поиск IDE открывался внутри свёрнутой панели | Явное действие раскрывает нужную область. Сворачивание во время запуска не отменяется его завершением |
| Закрытие активного файла/инструмента перескакивало к первому | Выбирается соседняя вкладка. Пустой редактор сохраняет доступ к панели инструментов |
| Split diff в узкой панели дробил строки до нечитаемых колонок | Автоматический unified на узкой панели, split на широкой; ручной выбор не сбрасывается |
| Критерии трекера разбивались на отдельные буквы | Нормализация строк и массивов на обеих границах. Повторный вход сохраняет выбранный разговор; title/description обновляются без сброса черновика |
| «Обсудить с агентом» теряло описание, версию, цель | Специализированные snapshots содержат выбранный объект и его факты. Они показаны компактным вложением с preview/удалением; текст сообщения остаётся коротким |
| Контекст мог засорять чат или изменяться после постановки в очередь | При отправке фиксируется текстовый snapshot; в истории он свёрнут. Очередь владеет этой версией. Вложения принадлежат разговору и переносятся в checkpoint |
| Фильтры трекера попадали в другой проект; спринт оставался «28» | Фильтры/выбранный спринт независимы по проектам. Новые спринты доступны в списках и редакторе; метрики относятся к выбранному спринту. «Мои открытые» исключает завершённые |
| Повтор Jenkins мог взять текущий сервер и default параметры | Повтор фиксирует исходный connection и параметры. Изменённая/недоступная цель блокирует повтор вместо подстановки другого стенда |
| Цвета кода различались между поверхностями | Общая Monokai для редакторов, запросов, diff и логов. В обеих темах оболочки код на тёмном фоне; розовый и комментарии слегка осветлены. Минимальный расчётный контраст токенов на проверенных обычных/diff фонах — 4,64:1 |

## Повторная критика

Вторая итерация обнаружила дополнительные ошибки, которых не видно в статическом эскизе: общий bootstrap добавлял заголовки внутрь новых вкладок из-за совпавшего атрибута; общий CSS задавал слишком маленькую фиксированную ширину вкладки; агентская презентация могла вытеснить текущую панель из компактной группы; фильтр «Мои открытые» включал завершённые задачи. Исправлены атрибуты, размеры, соседство при закрытии и проверки фактической видимости.

## Наблюдаемые сценарии

- Поиск IDE после сворачивания; запуск/ручное сворачивание; закрытие README с переходом к соседнему checkout; пустой редактор.
- Узкий Git → разворачивание → ручной выбор unified → изменение размера.
- Проект Atlas → Nova → Atlas сохраняет черновик и собственные фильтры.
- GC-249 → «Взять в работу» сохраняет два полных критерия; обсуждение → новый разговор → возврат восстанавливает контекст; отправка показывает свёрнутый snapshot.
- Новый спринт с названием/целью/выбранными задачами; показатели по этому спринту.
- Jenkins запуск с `feature/ux-audit`/ИФТ → повтор с теми же параметрами.
- Вкладки рабочих групп, стрелки клавиатуры, закрытие → сосед, перенос мышью, сброс раскладки.

VM-отчёты находятся в `design/review-evidence/`: `shell-context-audit`, `context-chip-audit`, `agent-interop-audit`, `ide-ux-audit`, `ide-language-audit`, `ide-git-audit`, `workspace-layout-audit`, `cluster-environment-audit`, `syntax-state-audit`, `browser-tools-audit`. Они проверяют фактические функции прототипа с локальными fixtures; визуальные проверки сохранены отдельно. Расчёт контраста: `syntax-contrast.json`. Это не полный аудит WCAG и не проверка реальных внешних действий.

## Что требует следующего этапа

Проверить то же поведение в настоящем Electron на Windows/ВАРМ: фоновые события, реальные LSP/DAP/PTY, очереди и отмена MCP, reconnect/unknown outcome, persistence и работа нескольких окон. Макет сохраняет часть настроек в localStorage, но не является долговечным хранилищем всей рабочей задачи. Серверные scopes и секреты должны оставаться проверяемыми в host, а не определяться текущей видимой панелью. Ограничения этого прохода не закрываются визуальным согласованием.

## Завершающий визуальный проход

Проверены 1280×720 и 768×720. При 768 чат и браузер образуют одну доступную группу вкладок без горизонтального переполнения оболочки; светлая тема браузера и тёмная тема чата проверены визуально. Список всех панелей открывается отдельной стрелкой группы. Браузер получил одну строку статуса вместо двух с доступом к профилю, viewport/zoom и браузеру агента. Повторная кнопка обсуждения кода убрана из внутренней панели IDE: остаётся общая контекстная команда в заголовке.

В окончательном широком просмотре чат и IDE имеют по 598 px высоты области панели; исходная ширина страницы равна ширине окна, ошибок JavaScript в наблюдаемом финальном сеансе нет. Скриншоты: `ux-final-dark.png`, `ux-final-768-dark.png`, `ux-final-768-light.png`. Это измерения макета в текущем браузере, а не замеры Windows-приложения.
