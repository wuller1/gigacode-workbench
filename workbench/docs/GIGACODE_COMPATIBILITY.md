# Совместимость с GigaCode CLI

**Актуализация целевой установки:** пользователь теперь ориентируется на GigaCode CLI **26.10.6**. Сначала прочитай его фактические executable/version/hash, справку и ACP capabilities. Датированное исследование ниже, включая свидетельства исходного RUNBOOK для 26.9.75, сохранено как история и не подтверждает поддержку или семантику новой сборки.

Проверено 9 октября 2026 года по публичной документации GitVerse и переданной пользователем обвязке `gigacode-bootstrap`. Целевая версия пользователя — **GigaCode CLI 26.9.75**, установленная на другом компьютере; версия сообщена пользователем. На этой машине runtime GigaCode 26.9.75 не проверялся. «Подтверждено» ниже означает описано в публичной документации, а не испытано на этой сборке; локальные свидетельства обозначены отдельно. Минимальные версии появления функций неизвестны: страницы не привязаны к релизу 26.9.75. При подключении подтвердить версию через `/about` и доступные команды через `/help`. Назначение Sprut и состав его MCP-инструментов пока неизвестны.

## Матрица возможностей

| Возможность | Статус | Подтверждённый контракт / граница знания |
|---|---|---|
| Постоянные инструкции | Подтверждено | Проектный `GIGACODE.md`, пользовательский `~/.gigacode/GIGACODE.md`, локальный `.gigacode/GIGACODE.local.md`. Локальный файл читается после проектного. Также читается существующий `AGENTS.md`; при запуске учитывать конфликты между инструкциями. [Memory](https://gitverse.ru/docs/ai/ai-assistant-gigacode/gigacode-cli/memory) |

Здесь установка не запускалась. Источники и границы приведены ниже. Имя `SYSTEM_PROMPT.md` само по себе ничего не подключает. |
| Append system prompt главной сессии | Не подтверждено | В проверенных публичных разделах и переданной обвязке не установлен отдельный контракт дополнения главного системного сообщения. Замена файла и добавление проектного контекста — разные механизмы. |
| `QWEN.md` | Не подтверждено для fork | Автоматическое чтение этого имени в GigaCode не установлено. Использовать `GIGACODE.md` либо явно добавлять нужный текст в контекст. [Memory](https://gitverse.ru/docs/ai/ai-assistant-gigacode/gigacode-cli/memory) |

Подпапки образуют namespace через `:`. Проектные команды имеют приоритет. TOML не подтверждён. [Команды](https://gitverse.ru/docs/ai/ai-assistant-gigacode/gigacode-cli/commands) |

Более разрешительный режим родителя может иметь приоритет над `approvalMode`; один этот параметр не гарантирует изоляцию. Fork использует общую рабочую директорию и не возвращает результат в основной диалог автоматически. [Субагенты](https://gitverse.ru/docs/ai/ai-assistant-gigacode/gigacode-cli/subagents) |

Это настройки хоста; пакет не переписывает их автоматически. [MCP](https://gitverse.ru/docs/ai/ai-assistant-gigacode/gigacode-cli/mcp) |

## Как применять SYSTEM_PROMPT.md

Документация подтверждает два разных механизма:

1. **Инструкции проекта.** `GIGACODE.md` загружается как контекст проекта и может ссылаться на файлы через `@path`, относительно себя. Это подтверждённый способ подключить подготовленный текст, но документация не устанавливает, что он заменяет системное сообщение хоста. [Memory](https://gitverse.ru/docs/ai/ai-assistant-gigacode/gigacode-cli/memory)
2. **Системные инструкции именованного субагента.** Markdown-тело файла агента документировано как его system prompt. Это относится к данному субагенту; замена промпта главной сессии из этого не следует. [Субагенты](https://gitverse.ru/docs/ai/ai-assistant-gigacode/gigacode-cli/subagents)

В существующий проектный `GIGACODE.md` можно добавить отдельный блок, сохранив действующие правила проекта:

```markdown
## Рабочий процесс Workbench

Применяй инструкции качества и восстановления контекста из
@gigacode-workbench/SYSTEM_PROMPT.md

Для запуска выбранного рабочего процесса прочитай
@gigacode-workbench/BOOTSTRAP.md
```

После загрузки проверить состав памяти через `/memory`. Для единичного запуска остаётся явное добавление того же файла через `@gigacode-workbench/SYSTEM_PROMPT.md` в запрос. Ни один из вариантов не меняет разрешения инструментов и не гарантирует соблюдение инструкций каждым вызовом.

### Локальное свидетельство замены главного промпта

В предоставленной пользователем поставке `<bootstrap-source>` есть конкретный механизм: `GIGACODE_SYSTEM_MD` хранит путь к файлу `system-gigacode.md`. Он описан в `INSTALL.md:51`, `RUNBOOK.md:25–29` и выводе `global/install-global:312`. `RUNBOOK.md:126` прямо фиксирует, что механизм работает; версия 26.9.75 и работоспособность текущей обвязки сообщены пользователем. `RUNBOOK.md:106` также описывает `GIGACODE_WRITE_SYSTEM_MD` для выгрузки промпта.

Это уточняет прежний вывод «механизм неизвестен»: у пользователя уже есть используемый способ замены. Проверенные публичные страницы его не описывают, а в переданной папке нет runtime GigaCode и результатов запуска, позволяющих независимо проверить обработку этих переменных. Маркер `GIGACODE-CUSTOM-1` в ответе модели полезен для диагностики, но один самоотчёт не доказывает, какой текст передан в system message. Append, правила приоритета и совместимость с последующими версиями остаются неизвестными.

При миграции сохранить резервную копию действующего промпта и настроек, зафиксировать версию и отдельно проверить заменяемый текст на этой сборке. Новый файл не следует накладывать поверх старых глобальных правил об обязательных полных проходах: они конфликтуют с выбором достаточного объёма работы. Переменные окружения и установка пользователя этим пакетом не изменяются. Подробности — [аудит прежней обвязки](BOOTSTRAP_AUDIT.md).

Для гарантированной записи каждого внешнего действия оболочке понадобятся подтверждённые точки перехвата до и после вызова инструмента. Инструкции модели и локальный журнал Workbench сами по себе не доказывают, что GigaCode записал все вызовы. Восстановление опирается на сохранённые данные и наблюдения; пропущенные события и неизвестные исходы явно остаются неизвестными.

## Как пользоваться текстовыми инструкциями сразу

Запустить обычную интерактивную сессию GigaCode в рабочем проекте. Файлы пакета можно держать внутри проекта, например в `gigacode-workbench/`. Добавить нужные Markdown-файлы через документированный синтаксис `@path`: содержимое попадёт в контекст. Ссылки на файлы — пользовательские инструкции, а не системное ограничение инструментов. [Команды](https://gitverse.ru/docs/ai/ai-assistant-gigacode/gigacode-cli/commands)

Пример запроса; заменить пути фактическими именами файлов пакета:

```text
@gigacode-workbench/SYSTEM_PROMPT.md
@gigacode-workbench/CORE.md
@gigacode-workbench/BOOTSTRAP.md

Применяй общие правила и маршрут запуска к задаче ниже.
Сначала проверь входные данные и загруженные инструкции.
Если файл недоступен, сообщи его путь, не придумывай его содержание.
Задача: <описание моей задачи>.
```

Этот способ не требует менять `settings.json`, устанавливать extensions или заменять существующий `GIGACODE.md`. При новой сессии нужно снова передать актуальный профиль, состояние задачи и необходимые артефакты. Для меньшего контекста загружать только текущий маршрут и его входы.

Нативные адаптеры опциональны и зависят от функций вашей сборки. Шаблон `adapters/gigacode/commands/workbench.md` можно добавить в проект как `.gigacode/commands/workbench.md`, если такого файла ещё нет, затем проверить его появление в `/help`. Он запускает тот же текстовый процесс через `/workbench <задача>`. Если адаптер не распознаётся, использовать документированный вариант `@...`. [Команды](https://gitverse.ru/docs/ai/ai-assistant-gigacode/gigacode-cli/commands)

## Что проверить перед автоматическим адаптером

1. Зафиксировать номер и происхождение сборки, список команд и обнаруженных инструментов. Не сохранять секреты из настроек.
2. В тестовом проекте проверить чтение одного файла, команду без побочных действий, один субагент и один skill. Сверить результат с ожидаемым.
3. Отдельно проверить фактические ограничения инструментов. Промпт с запретом записи не заменяет ограничение прав учётной записи или allowlist runtime.
4. Подтвердить неинтерактивный транспорт по документации/справке именно этой сборки. Затем проверить события, завершение, отмену, продолжение и неизвестный исход внешнего вызова.
5. До такой проверки оставить драйвер интерактивным. JSON-документы пакета являются контрактом будущей оболочки; GigaCode не обязан сам их исполнять.

Не путать продукт GitVerse/Sber с одноимёнными сторонними проектами `gigacode` или экспериментальным `gc-cli`: совпадение названия не подтверждает совместимость.
