# Определение затронутой документации

`tools/docs-impact.ps1` читает изменения Git и проектную карту «источник → документ», затем возвращает JSON. Он помогает выбрать область проверки без полного обхода документации, не переписывает файлы и не оценивает смысловую актуальность текста. Windows PowerShell 5.1 и локальный Git; сеть, установщики и hooks не используются.

Сначала подготовьте карту на основе существующих правил проекта. Репозиторий заново настраивать не нужно. Пример `config/docs-map.example.json` намеренно содержит `configured: false`: пока пути и исключения не подтверждены, результат — `needs_configuration`.

```sh
powershell -NoProfile -File gigacode-workbench/tools/docs-impact.ps1 -Repo . -Map docs-map.json
powershell -NoProfile -File gigacode-workbench/tools/docs-impact.ps1 -Repo . -Map docs-map.json -Staged
powershell -NoProfile -File gigacode-workbench/tools/docs-impact.ps1 -Repo . -Map docs-map.json -Base main
```

Без режима сравнивается рабочее дерево с `HEAD`, включая staged, unstaged и неигнорируемые untracked файлы. `-Base` меняет исходный commit, а не использует merge-base. `-Staged` анализирует только индекс относительно `HEAD`; незакоммиченный текст документа не принимается за часть будущего коммита. Дополнительное чтение unstaged-списка служит только для предупреждения `stale_index_docs`. Нужен существующий исходный commit; unborn-репозиторий возвращает ошибку.

## Карта версии 1

- `configured`: явный boolean; выставляется в `true` после проверки карты для данного проекта.
- `rules`: список `{id, sources, documents, reason}`. `id` уникален, `sources` — непустой список шаблонов, `documents` — непустой список точных путей, `reason` объясняет связь. Изменение самого указанного документа тоже требует проверки.
- `ignores`: список `{pattern, reason}` с явным обоснованием неприменимости документации. Совпавшее правило имеет приоритет над исключением. Для переименования исключение должно покрывать оба имени.

Пути относительны корню Git и используют `/`; абсолютные пути, `..`, обратные слеши и документы с symlink/junction в пути запрещены в этой PowerShell-реализации (включая ссылки внутрь проекта). Шаблоны соответствуют шаблонам `fnmatchcase` исходного формата: `*` включает `/`, `?` обозначает один символ, `[abc]` — набор; `**` не имеет отдельной семантики. Например, `src/api/*` покрывает и вложенные файлы. Это собственный формат, не Git pathspec. Карта не требует чтения содержимого исходников или документов и не доказывает их наличие в индексе.

## Как читать результат

| Поле / статус | Значение |
|---|---|
| `changed_files` | Изменения и статусы Git; переименования сохраняют `old_path` и `new_path`, оба участвуют в сопоставлении |
| `affected_documents` | Документы, правила, причины и связанные изменённые пути; `document_changed` обозначает наличие изменения, не его достаточность |
| `unmapped_changes` | Изменения без связи или обоснованного исключения; их нельзя считать безопасными для документации |
| `stale_index_docs` | В staged-режиме документ изменён только в рабочем дереве; это изменение не входит в анализируемый commit |
| `needs_review`, exit 1 | Есть затронутые документы или неизвестные связи; требуется решение по содержанию |
| `no_op_candidate`, exit 0 | В области анализа нет изменений либо каждое имеет явное исключение и не затрагивает правило. Это кандидат на пропуск обновления, не сертификат качества документации |
| `needs_configuration` / `error`, exit 2 | Карта ещё не принята либо анализ невозможен; это не успешная проверка |

`semantic_freshness` всегда равен `not_evaluated`. Время изменения, наличие документа или его правка не превращаются в «актуально». Уточнение карты после обнаружения неизвестного файла должно объяснять его связь или исключение, а не просто убирать неудобный результат.

Git-запросы пакетные: корень, проверенный commit, один diff и один список untracked либо unstaged-путей; число запросов не растёт с числом связей. Вызов идёт списком аргументов с `shell=False`, без external diff/textconv/fsmonitor; revision проверяется до diff, значение с начальным `-` отклоняется. На запрос установлен timeout 30 секунд, после получения проверяется предел вывода 8 MiB, на анализ — 10 000 записей изменений; превышение даёт ошибку. Это предел принимаемого результата, а не ограничение памяти процесса Git.

Untracked-поиск соблюдает Git ignore и дополнительно исключает каталоги `node_modules/`, чтобы не перечислять установленные зависимости; отслеживаемые Git изменения в таких каталогах остаются в diff. Прочие игнорируемые файлы также вне области анализа. Субмодули рассматриваются как изменённый путь родительского репозитория; их содержимое отдельно не обходится. Ошибка или неизвестная связь не становится `no_op_candidate`.

Проверка helper: `powershell -NoProfile -File gigacode-workbench/tests/test-docs-impact.ps1`. Тесты используют временные локальные репозитории и не обращаются к remotes.
