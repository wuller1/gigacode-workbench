# Графика и движение GigaCode UI

Выбор для личного приложения: **собственные 29 SVG-иконок из [ICON_LIBRARY](ICON_LIBRARY.md), системные шрифты по имени, собственная простая CSS-анимация состояния работы**. Без фирменных логотипов, чужих иллюстраций, Lottie/GIF, декоративного героя и звукового autoplay. SVG уже находятся в пакете; их интеграция в приложение и проверка настоящего экрана ещё предстоят. Следуй [DESIGN_IMPLEMENTATION_GUIDE.md](DESIGN_IMPLEMENTATION_GUIDE.md), режиму `personal_fast` и текущим компонентам приложения.

Графика объясняет действие или состояние. Не добавляй иконку к каждой строке текста. Один смысл получает один glyph; новое состояние сначала различается словами, затем формой и цветом. Анимация не создаёт факты: её остановка не завершает операцию, а вращение не доказывает исправность CLI.

## 1. Что брать и как сохранить права

Названия ниже — ключи нашего [assets/icons.json](../assets/icons.json), `schema_version: 1`; каждому соответствует готовый файл в [assets/icons](../assets/icons/). Формы созданы для этой задачи из простых линий, дуг и прямоугольников; готовые сторонние paths не копировались. Общеупотребительные UI-знаки могут быть похожи в разных наборах: это не обещание уникальности каждого плюса или стрелки по отношению ко всем существующим изображениям.

Встроить нужные статические SVG-компоненты или небольшой renderer проверенных shapes по [ICON_LIBRARY.md](ICON_LIBRARY.md). Это не требует установки icon-пакета или обновления framework. Сохранять SVG и JSON согласованными; источник изменения и hash — в принятой записи проекта. Не применять raw HTML/произвольный attribute spread, icon CDN, удалённые SVG или webfont при запуске приложения.

Пользователь разрешил графические файлы в почтовом пакете: собственные SVG и PNG-превью — допустимая часть поставки наряду с текстом. Это не разрешение включать исполняемые scripts или binaries. Для будущих сторонних изображений, шрифтов и других assets остаётся проверка конкретного источника, версии, лицензии и вложенных материалов по [ASSET_RIGHTS.md](ASSET_RIGHTS.md); публичный репозиторий сам по себе не заменяет разрешение на использование.

Использовать font stack из дизайн-руководства: `system-ui, 'Segoe UI', sans-serif` и `ui-monospace, Consolas, monospace`. Это имена локально доступных шрифтов с fallback, без извлечения/включения font binary. Изображения и наборы шрифтов здесь не требуются. Уже проверенную запись прав переиспользовать до изменения version/hash, лицензии, происхождения или способа применения; повторный аудит на каждой правке не нужен.

## 2. Небольшой словарь иконок

Общее правило: компактная иконка в строке/панели **16×16 CSS px**, более заметная отправка/пустое состояние — **20×20**. Исходная сетка нашего набора 20×20, `stroke-width=1.5`, `fill=none`, round ends/joins; при размере 16 обводка масштабируется вместе с геометрией. Не использовать non-scaling stroke для этого набора. Цвет — `currentColor` из выбранного токена, не цвет конкретного файла и не рандомная палитра статусов. Наследование цвета действует для inline SVG; отдельный `<img>` не наследует цвет родителя внутрь файла.

Иконка и цель нажатия — разные размеры: icon-only button 32×32, обычная кнопка min-height 36, отправка 40; принятый touch-сценарий использует 44. Между icon и label — 8. Иконка не сжимается при длинном русском label; label переносится или получает место. О требованиях доступности и исключениях целей — [DESIGN_QUALITY.md](DESIGN_QUALITY.md).

## 3. Статусы: источник факта важнее картинки

Имена ниже — **проектная модель представления**, не новые ACP methods, поля CLI или обязательные значения существующего store. Adapter сопоставляет её с реально наблюдаемыми событиями установленной версии. Храни отдельно ход операции, соединение и сведения retry: потеря transport не должна стирать известный результат; декоратор не управляет session state.

| Представление | Когда его можно показать | Графика и точный смысл |
|---|---|---|
| `working` | Владелец операции подтвердил начало/in-flight; нет известного ожидания/terminal outcome | Собственная дуга 16, 900 ms linear; «Выполняется» или подтверждённое действие. Не писать «Думает», если это лишь догадка по отсутствию текста |
| `waiting` | Известна очередь, ожидание разрешения или внешнего результата | Статичный clock + «В очереди» / «Ожидает разрешения» / «Ожидает результата». Отсутствие токенов само по себе не доказывает эту причину |
| `retry` | Существующий владелец retry сообщил о назначенной попытке/ожидании | Статичный clock + «Повтор назначен…». Deadline/номер только при наличии факта; без deadline — «Ожидается повтор». Не крутить glyph «обновить» как обещание активной работы |
| `disconnected` | Есть подтверждённая потеря соединения | Статичный warning + «Соединение потеряно»; отдельно сохранить известный или неизвестный исход операции. Не объявлять автоматически отмену/ошибку самого запроса |
| `unknown` | Итог начатой операции не установлен, например после обрыва | Статичный unknown + «Исход неизвестен». Доступные действия сверяют состояние; нельзя слепо повторить prompt/MCP write ради исчезновения значка |
| `cancel_requested` | Запрос отмены действительно отправлен, terminal outcome ещё не получен | Статичный clock + «Отмена запрошена». Не показывать «Остановлено», не освобождать busy slot по одной отправленной notification; доступность новых действий определяет host |
| `completed` | Получен подтверждённый успешный terminal outcome конкретной операции | Статичный check + «Ответ получен» / «Копирование завершено» / другой точный результат. Завершение ответа не доказывает, что код исправлен и проверки прошли |
| `failed` / `cancelled` | Получен соответствующий конечный результат | warning + «Не выполнено: причина» / текст «Остановлено». Это отдельные итоги, не варианты зелёного completed; stop обозначает доступное действие остановки |

Если отмена была запрошена, но пришёл успешный результат до подтверждённой остановки, покажи действительный исход и пояснение при необходимости. Если completed уже известен и позже пропало соединение, результат остаётся completed, а соединение показывается отдельной заметкой. При `cancel_requested + disconnected` оба факта сохраняются: «Отмена запрошена; связь потеряна, итог неизвестен». Не своди их к случайному «последнему пришедшему статусу».

У сессий A/B отдельные статусы. Анимация активного чата не запускает working у соседнего. В sidebar достаточно статичного glyph/текста; **единственная непрерывная анимация — у видимого текущего рабочего действия**, пока она разрешена. В background/скрытой панели остановить декорацию, но не задачу. Не мигать фоном всего окна и не трясти кнопки ошибки.

## 4. Собственный motion recipe

Начальные значения согласованы с дизайн-руководством. Они проектные, не норматив доступности и не измеренная производительность. Без заимствованных keyframes, анимационных файлов или дополнительных motion dependencies.

| Элемент | Timeline | Примечание |
|---|---|---|
| Working arc | 0 ms: 0° → 225 ms: 90° → 450 ms: 180° → 675 ms: 270° → 900 ms: 360°; linear, повтор | Только transform; одна неподвижная геометрия 16×16, никаких процентов и меняющейся длины «прогресса» |
| Hover/pressed | Старые background/border → новые за 120 ms, ease-out | Focus ring появляется сразу, не ждёт анимацию; не анимировать весь текст opacity |
| Открытие inspector/menu | 0 ms: opacity 0, translateX(8 px) → 160 ms: opacity 1, translateX(0); cubic-bezier(0.2, 0, 0, 1) | Контейнер уже занимает конечное место; не анимировать width/grid каждой колонки. Для меню допустим fade без translate |
| Раскрытие tool details | Контент открывается сразу; chevron 0° → 180° за 120 ms | Не делать auto-height анимацию многотысячного log; закрытие возвращает glyph за 120 ms |
| Завершение/ошибка/permission | Статичное новое состояние сразу после события | Без confetti, shake, зелёного preview «наверняка готово» и бесконечного celebration |
| Copy feedback | После успешного clipboard result: «Скопировано» и check; через 1500 ms вернуть обычную подпись | Зарезервировать ширину, не сдвигать соседей. Ошибка сохраняется до понятного следующего действия, не исчезает по этому таймеру |

Собственный CSS-пример дуги, который нужно адаптировать к существующим именам/токенам. `is-animating` выставляется только для разрешённой видимой декорации working; рядом всегда находится текст статуса. Этот класс не отправляет, не отменяет и не повторяет операции.

```css
.wb-work-arc {
  display: inline-block;
  flex: 0 0 16px;
  box-sizing: border-box;
  width: 16px;
  height: 16px;
  border: 2px solid transparent;
  border-top-color: currentColor;
  border-right-color: currentColor;
  border-radius: 50%;
  transform-origin: 50% 50%;
}
.wb-work-arc.is-animating {
  animation: wb-work-turn 900ms linear infinite;
}
@keyframes wb-work-turn {
  from { transform: rotate(0deg); }
  to   { transform: rotate(360deg); }
}
[data-motion="off"] .wb-work-arc {
  animation: none;
  transform: none;
}
@media (prefers-reduced-motion: reduce) {
  .wb-work-arc {
    animation: none !important;
    transform: none !important;
  }
}
```

Значение `data-motion` — предлагаемый локальный атрибут на корневом контейнере UI, не настройка CLI. Собственное «уменьшить движение» и системное `prefers-reduced-motion` объединяются в пользу меньшего движения: arc неподвижна, переходы панелей/chevron/hover мгновенные, текст остаётся. Переходы из таблицы вне CSS-примера тоже обязаны учитывать настройку; пример одной дуги не выключает автоматически анимации всего приложения. [MDN: prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)

У мгновенных операций не задерживать результат, чтобы пользователь успел увидеть spinner. Место для glyph зарезервировано заранее; если нужно подавить мелькание, задержать **только появление дуги** на 150 ms, оставляя текст состояния немедленным. Если операция закончилась раньше, дуга не появляется. Окончание анимации не callback завершения бизнес-операции. Не добавлять искусственную посимвольную печать, задерживающую уже полученный ответ ради эффекта.

Countdown разрешён только от фактического `retryAt` владельца: показывать округлённые вверх оставшиеся секунды, обновлять не чаще 1 раза/с, ограничивать снизу нулём. После срока без подтверждённого старта писать «Ожидается начало повторной попытки», не переводить самовольно в working. Перевод часов/перезапуск не должен давать отрицательное время. Эти значения — пояснение ожидания, не новый планировщик и не дополнительный retry layer.

## 5. Пустые состояния и тихие служебные области

Пустой чат: icon chat 20, заголовок «Начните с задачи», одна короткая подсказка и существующий composer. Если проект не выбран, один действующий путь «Открыть проект»; не рисовать неработающие примеры и каталог возможностей. Empty inspector: file 20 + «Выберите материал в чате»; закрытая панель не резервирует место. Нет результатов поиска: «Ничего не найдено» + текущая область/запрос и возможность изменить их.

Композиция — собственные простые блоки: glyph, заголовок, пояснение, одно необходимое действие; gap 8/12, без декоративного SVG-пейзажа. Не имитировать фактические данные серыми «готовыми карточками». Пока данные реально загружаются, достаточно текстового состояния и одной дуги; skeleton shimmer не добавлять. Offline/permission/error не являются empty state и сохраняют причину и восстановление.

Терминал, browser и file viewer используют тот же размер glyph, текстовые подписи и tokens. Не загружать favicon внешнего сайта ради tab icon по умолчанию; используй browser. Для пользовательского изображения thumbnail допускается из реально открытого материала с его границами доверия, а не из чужого сайта для украшения. Звуки не включать автоматически; звуковая тема в текущий объём не входит.

## 6. Доступность и производительность без ложных обещаний

Факт и движение отделены: текст статуса доступен без анимации, цвет дополнен смысловой подписью, контраст определяется реальными tokens/фоном. Для `working`, `waiting`, `retry`, `disconnected`, `unknown`, `cancel_requested` и конечных исходов проверь, что одну подпись нельзя спутать с другой при отключённых цвете и motion. «Отмена запрошена» и «Остановлено» — разные сообщения.

Выдели одну умеренную live-region для значимых переходов текущего чата; сам transcript не должен автоматически озвучивать каждый token, glyph и tick countdown. Не повторять объявление неизменившегося статуса при rerender. Ожидание разрешения сообщить один раз без внезапного переноса focus; ошибка фоновой задачи остаётся в её строке, а не перебивает чтение каждую секунду. Проверь фактическое поведение screen reader, не объявляй его работающим только по наличию ARIA.

Не создавать JS frame-loop для вращения и отдельный interval на каждую строку истории. Для подтверждённого deadline достаточно одного обслуживаемого видимого clock; скрытые countdown не обновлять ради декора. Не включать `will-change` на сотнях элементов. Transform/opacity — предпочтение, **не гарантия** compositor-only или отсутствия jank: это зависит от настоящей разметки и Electron.

На первом добавлении анимации проверь в настоящем Electron тот же сценарий до/после: 20–30 секунд streaming + набор русского текста + scroll + переключение чата. Запиши build, viewport/scale, устройство/refresh rate, число видимых движущихся элементов и наблюдаемую задержку ввода; при подозрении сними короткий performance trace. FPS/jank и long tasks отмечать по измерению, не писать «стабильные 60 FPS» по screenshot. Один frame budget зависит от частоты дисплея; нельзя принимать любое устройство как 60 Hz. При дефекте убрать лишнее движение, сохранив честный статус.

## 7. Одно короткое задание исполнителю

```text
Задача: добавить [конкретный glyph / working indicator / нужные статусы] в существующий [компонент].
Режим personal_fast; менять только [файлы]. CLI, session ownership и retry policy не менять.
Вход: текущая реализация; token refs; выбранные строки GRAPHICS_AND_MOTION; реальные state/event refs.
Assets: [имя и hash собственного assets/icons/<name>.svg или shapes из icons.json] либо собственный CSS primitive; без CDN/font binary/Lottie.
1. Проверь имя в ICON_LIBRARY, выбранный SVG/JSON renderer и источник каждого нужного состояния. Не придумывай aliases/APIs.
2. Реализуй минимальный diff; label и hit area обязательны, факты состояния не определяются анимацией.
3. Проверь только затронутые переходы: normal + плохой случай + reduced motion в том же build.
4. Сохрани screenshot/короткую запись, фактические шаги и измерения; не изображай fixture как реальный CLI.
Верни: что изменено; права/источники; pass/fail/unknown по выбранным случаям; evidence и build.
Без live Electron: реализация/fixture готовы, live-приёмка incomplete; не утверждать плавность и исправность UI.
```

Стартовые случаи для **введения всей статусной строки**, не для каждой смены иконки: (G1) working → completed с настоящим результатом; (G2) waiting/retry не выглядят working, нет выдуманного countdown; (G3) обрыв + неизвестный исход, отмена не считается подтверждённой раньше terminal outcome; (G4) reduced motion и keyboard, текст остаётся понятным. Добавить failed/cancelled, если они затронуты. Сложные редкие события разрешено вызвать безопасной fixture, но она не заменяет обязательную проверку реальной интеграции.

После успешной приёмки неизменившийся glyph/provenance/motion recipe не проверять заново полным набором. На микро-правку назначить конкретный затронутый случай.
