# Графика, шрифты и права на материалы

Правило пользователя: соблюдать авторские права и условия лицензий даже для личного инструмента. Это практическая инструкция работы с материалами, а не юридическая гарантия отсутствия любых претензий. Проверено по первичным источникам 2026-10-09; конкретную версию зависимости проверять при подключении.

## Принятые решения

В дополнительный набор [корпоративных референсов](CORPORATE_DESIGN_REFERENCES.md) включено разрешённое пользователем заимствование Plasma / SDDS SERV: [24 точные пары CSS-токенов](../assets/sber-reference/plasma-token-subset.json) из light/dark CSS пакета @salutejs/sdds-themes 0.84.0-dev.0, commit fe399bad3bfa7ffe4eea233c258d944c866e9815. Сохранена полная [MIT-лицензия, Copyright (c) Salute Devices](../assets/sber-reference/LICENSE.txt); пути, строки, hashes и изменения указаны в [SOURCE.md](../assets/sber-reference/SOURCE.md). [Optional preset](../config/design-presets/sber-plasma.json) содержит восемь точных mappings; остальные semantic-цвета и правила — явно обозначенная собственная адаптация. Это snapshot источника, не рекомендация устанавливать prerelease. Font binaries, логотипы, screenshots, сторонние иконки и SDK компонентов не включены; лицензия темы на них не обобщается. Сохранять notice при переносе. Базовая тема Workbench остаётся собственной.

- Компоновка, палитра, размеры и анимации нашей оболочки проектируются самостоятельно. Внешние интерфейсы изучаются для понимания общих принципов. Не переносить screenshot, иллюстрации, логотипы, тексты, фирменные шрифты или готовые темы без установленного права использовать именно эти материалы. Пользователь отдельно разрешил перенос сберовских материалов; разрешённые условиями конкретного источника элементы можно включать с происхождением и обязательными уведомлениями. Это не устанавливает права на все материалы бренда.
- В UI_REFERENCES находятся обычные ссылки на официальные страницы. Они не дают лицензии на материалы этих страниц. Внешние screenshots не включаются в приложение или почтовый пакет и не загружаются автоматически. Пользователь отдельно разрешил пересылать собственную графику: SVG-иконки и PNG-превью могут входить в пакет вместе с текстом. Это исключение для графики, а не разрешение включать исполняемые scripts или binaries.
- Для иконок создан собственный набор: [ICON_LIBRARY.md](ICON_LIBRARY.md), [assets/icons.json](../assets/icons.json) и **29 готовых файлов SVG** в [assets/icons](../assets/icons/). Формы нарисованы для этой задачи; готовые paths сторонних наборов не копировались и не скачивались. Простые общепринятые UI-знаки могут быть похожи в разных интерфейсах; происхождение «создано для этой задачи» не обещает абсолютную уникальность каждой формы и не заменяет проверку будущих заимствований. В реестре проекта фиксировать собственный источник и hash файлов, без выдуманной лицензии третьей стороны.
- Шрифты по умолчанию — уже доступные системные через font stack. Файлы Segoe UI, Consolas или другого установленного шрифта не копируются в приложение. При необходимости поставлять собственный font binary нужно отдельно выбрать лицензированную семью и проверить её точные файлы. Для OFL нужно сохранить copyright и лицензию, учитывать Reserved Font Names и правила модификации; название OFL не заменяет чтение условий. [Официальный текст SIL OFL](https://openfontlicense.org/open-font-license-official-text/)
- Индикаторы работы и переходы реализуются собственной простой CSS-графикой. Готовые анимации Lottie, чужие mascots, фотографии и декоративные иллюстрации не нужны базовому рабочему экрану. Их добавление в будущем требует отдельной записи происхождения, а не предположения «найдено бесплатно».
- Установленный GigaCode Desktop служит источником доступных наблюдений о совместимости ACP. Не извлекать из него графику, шрифты или закрытый код для переноса; не обходить защиту. Ссылки на MIT/Apache проекты в OPEN_SOURCE_RESEARCH не распространяют эти лицензии на чужой Desktop.

Авторское право различает идеи/методы и конкретное выражение; публичное размещение само по себе не делает материал свободным для любого использования. Применимость исключений зависит от законодательства и обстоятельств. Поэтому здесь используется положительное подтверждение разрешённого применения, а не автоматическое оправдание личным использованием. [WIPO: вопросы об авторском праве](https://www.wipo.int/en/web/copyright/faq-copyright)

## Короткая проверка при добавлении материала

1. Найти официальный источник и точный файл/пакет: версия или commit и, для локальной копии, hash. Проверить владельца, LICENSE, copyright/NOTICE и вложенные исключения. Лицензия кода не обязательно покрывает demo-картинки, шрифты, логотипы и сторонние assets.
2. Сопоставить разрешение с реальным использованием: включение в Electron, модификация, копирование исходника, распространение вместе со сборкой. Брендовые обозначения проверяются отдельно; open-source лицензия не означает разрешение выдавать приложение за чужой продукт.
3. Сохранить необходимые тексты и атрибуцию в доступном составе приложения, например `THIRD_PARTY_NOTICES` и каталог лицензий. Список названий и URL не заменяет обязательный полный текст лицензии. Конкретное расположение зависит от условий выбранных материалов.
4. Записать решение в существующий dependency/asset register проекта. Проверять повторно только при изменении версии, файла, лицензии или способа применения. Для неизменённого набора не запускать аудит на каждом небольшом UI-изменении.
5. Если разрешение не установлено — не добавлять спорный материал. Выбрать самостоятельную графику или подтверждённо подходящий аналог и продолжить независимую работу; не считать `unknown` успешной проверкой.

Минимальная запись (можно строкой существующей таблицы, отдельная база не нужна):

| Материал | Официальный источник + версия/commit | Локальные файлы/hash | Лицензия/разрешение и применимые исключения | Способ использования | Обязательные notices и их расположение | Решение + дата |
|---|---|---|---|---|---|---|

Для собственной графики указать происхождение «создано для этой задачи», без выдуманного автора или лицензии третьей стороны. Генерация моделью не служит автоматическим доказательством отсутствия чужих элементов: проверить отсутствие заимствованных брендов, персонажей и заметного воспроизведения конкретного произведения.

## Перед сборкой и передачей

Сверить только новые/изменённые включённые материалы с реестром и фактическим содержимым сборки. Не включать незаявленные font binaries, demo assets и картинки из документации зависимостей. Убедиться, что выбранный сборщик сохранил обязательные лицензии/уведомления сторонних материалов. Для собственной графики проверить соответствие SVG исходным shapes и отсутствие незаявленных вложений; графические файлы не должны содержать script, внешние загрузки или исполняемые вставки. Отчёт различает «источник проверен», «включено в пакет материалов», «включено в сборку приложения» и «проверено в готовой сборке». Сейчас подготовлены инструкции, собственные SVG и указанный выше лицензированный subset Plasma; целевое приложение ещё не проверялось. Сохранить почтовое ограничение на исполняемые файлы: разрешение на SVG/PNG его не отменяет.
