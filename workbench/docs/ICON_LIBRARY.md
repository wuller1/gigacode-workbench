# Собственная библиотека иконок

Дата: 2026-10-10. Для этого пакета заново нарисованы 34 простых векторных знака. Готовые иконки сторонних библиотек не скачивались, SVG paths из Lucide и других наборов не копировались. Это описание происхождения работы, не юридическая гарантия исключительной новизны: общеупотребительные знаки вроде плюса и стрелки естественно похожи в разных интерфейсах.

Иконки поставляются **прямыми графическими файлами** в [assets/icons](../assets/icons/). Их можно пересылать и использовать отдельно. [assets/icons.json](../assets/icons.json) хранит те же формы для небольшого типизированного renderer. Ни один вариант не требует генератора, пакета иконок или сетевой загрузки при работе приложения.

## Рисунок и размеры

Общая сетка — `viewBox="0 0 20 20"`, обводка `1.5`, скруглённые концы и соединения, отсутствие заливки. Основные контейнеры слегка прямоугольные; насыщенность линий и наружные отступы согласованы. Цвет задаётся через `currentColor` при inline-встраивании. Не добавляй каждому знаку собственный цвет, фон или тень: значение состояния передаётся общим семантическим цветом интерфейса и текстом.

Основной размер — 20 CSS px; компактный — 16 CSS px с пропорциональным масштабированием. Не применять `vector-effect="non-scaling-stroke"`: в 16 px должна масштабироваться и обводка. Размер рисунка не равен зоне нажатия: иконка остаётся внутри кнопки с достаточной областью взаимодействия и видимым focus по дизайн-контракту приложения. Не уменьшаются размеры кнопок ради плотности списка.

Читаемость в 16/20 px — проектная цель, которую нужно проверить в настоящем интерфейсе на целевой системе, масштабе экрана и выбранном фоне. Статическая проверка файлов не подтверждает runtime-отрисовку, контраст, доступность или узнаваемость пользователями.

## Контракт JSON renderer

Корень: `schema_version: 1`, `viewBox: "0 0 20 20"`, `strokeWidth: 1.5`, `strokeLinecap: "round"`, `strokeLinejoin: "round"`, `icons: { [name]: { label: string, shapes: Shape[] } }`. Список имён ограничен приведённым каталогом. `label` — краткое описание изображения, а не готовая подпись любого действия с ним.

У каждого Shape есть `type` и только перечисленные поля:

| type | Допустимые поля |
|---|---|
| path | `d`: строка SVG path data |
| rect | `x`, `y`, `width`, `height`, `rx`: числа |
| circle | `cx`, `cy`, `r`: числа |
| line | `x1`, `y1`, `x2`, `y2`: числа |
| polyline | `points`: массив числовых пар `[[x,y], …]` |

Renderer принимает только эту схему и известную версию. Проверяет конечность чисел, допустимые диапазоны координат, положительные размеры, структуру пар и отсутствие лишних полей. `d` разрешает только команды SVG path и числовые параметры, включая разделители; оно передаётся как значение атрибута `d`, не исполняется и не интерпретируется как разметка. Для текущего набора достаточно команд `M`, `L`, `H`, `V`, `A`, `C`, `Q`, `Z`; аргументы нужно валидировать по синтаксису выбранного parser, а не считать одну регулярную проверку полной валидацией SVG.

Создавать SVG и формы через framework-компоненты или `createElementNS`, с фиксированным allowlist элементов/атрибутов. `polyline.points` сериализовать из проверенных числовых пар. `fill="none"` и `stroke="currentColor"` задаёт renderer. Не применять raw HTML, `innerHTML`, `dangerouslySetInnerHTML` или универсальный spread произвольных атрибутов из JSON. В наборе нет script, событий, style, href, foreignObject, use, фильтров, внешних изображений и загружаемых шрифтов; renderer не должен добавлять их поддержку ради этих файлов. SVG namespace — стандартный идентификатор формата, не сетевой запрос.

Для внешнего SVG через `<img>` задавать корректный `alt`; родительский CSS `color` не передаётся внутрь такого отдельного документа. Для цвета интерфейса использовать безопасное inline-встраивание форм из JSON или проверенный статический SVG-компонент. Не загружать неизвестный SVG как HTML ради изменения цвета.

## Доступность и состояния

Отдельные файлы содержат `<title>`, `role="img"` и `aria-label`. В кнопке с доступным именем иконка декоративная: убрать собственный title/aria-label, задать `aria-hidden="true"`, а имя оставить кнопке. Если рядом видимый текст полностью описывает изображение, оно тоже декоративное. Tooltip дополняет доступное имя, не заменяет его. Не делать сам SVG отдельной точкой Tab.

Примеры точных имён кнопок: «Закрыть обсуждение», «Остановить исполнителя», «Открыть изменения», «Копировать путь». Для переключателя панели или раскрытия дерева отражать действительное состояние через `aria-expanded`/`aria-controls` на управляющем элементе. Название glyph не определяет поведение компонента.

| Наблюдаемое состояние | Знак и подпись |
|---|---|
| Действие или проверка успешно закончены и имеют соответствующее свидетельство | `check` + точная подпись результата |
| Workflow `completed` | `check` + «Этапы завершены»; это не отдельное доказательство отсутствия дефектов или разрешение релиза |
| `waiting_input` | `question` + «Нужен ответ» |
| Очередь, ожидание подтверждённой повторной попытки или `cancel_requested` | `clock` + «В очереди», «Ожидание» или «Останавливается» соответственно |
| `blocked`, `blocked_budget`, `needs_rework`, failed check | `warning` + конкретная причина; разные состояния не сливаются в один статус |
| Неизвестный исход, interrupted_unknown, отсутствующая проверка | `unknown` + «Исход неизвестен» или «Не проверено» |
| `cancelled` | Текст «Отменено»; квадрат `stop` остаётся знаком действия, а не доказательством отмены внешнего процесса |

Для работающего исполнителя использовать текст и предусмотренный интерфейсом индикатор активности; `clock` не выдаёт выдуманный прогресс. Цвет, форма и анимация не должны быть единственным различием между ожиданием, успехом и проблемой. Текущие glyphs не вводят новых workflow/ACP статусов.

## Проверка при интеграции

Кнопки собственного заголовка окна: [window-minimize](../assets/icons/window-minimize.svg), [window-maximize](../assets/icons/window-maximize.svg), [window-restore](../assets/icons/window-restore.svg) и существующий [close](../assets/icons/close.svg). Название доступного действия определяется подтверждённым состоянием окна. Свернуть окно, скрыть панель и отменить задачу — разные действия.

Сначала сопоставить SVG и JSON по имени и геометрии, проверить отсутствие лишних атрибутов. Затем посмотреть весь набор в 16/20 px на реальных поверхностях приложения; отдельно проверить плотные `agents`, `settings`, `diff`, внутренние просветы `attach`, точки `more` и `warning`. Проверить обрезание, вертикальное выравнивание в кнопках и строках, disabled/hover/focus, экранный диктор и масштаб ОС. Если знак не читается, упростить его геометрию и повторить адресное сравнение; не подменять весь набор новой библиотекой без решения пользователя.

Изменение glyph сначала вносится в JSON, затем синхронно — в одноимённый SVG. Поставка содержит готовые файлы, поэтому build-time генератор не обязателен. Не утверждать, что эти исходники уже интегрированы или проверены на Windows, пока такой проверки не было.
