# Итерационный аудит пакета 1.2.0

Дата: 2026-10-10. Это аудит инструкций и демонстрационного интерфейса. Исходники пользовательского GigaCode UI находятся на рабочем компьютере; исправление этого приложения, реальный ACP и Windows PowerShell 5.1 здесь не проверялись. Итоги упаковки и временной установки — в [VALIDATION](VALIDATION.md).

## Итерация 1 — полнота продукта и расположение интерфейса

Проверены пользовательские требования и рабочие пути: Project → Tasks → роли, самостоятельный план агента, артефакты, вопросы, управление сессиями, инструменты, очередь, исполнители и восстановление. [Матрица покрытия](REQUIREMENTS_COVERAGE.md) связывает требования с конкретными документами и проверками; наличие строки не означает готовую функцию.

Исправлены перегруженный заголовок и нелогичное размещение переключателя задач. Проекты и задачи открываются слева; разговор находится в центре; инструменты доступны через правый rail. Убраны обязательные верхние вкладки задачи и постоянно раскрытые сведения. Браузер и терминал получили независимое представление; скрытие не является закрытием процесса.

[Анализ решений](COMPETITOR_FEATURE_PLAN.md) содержит 33 функциональные идеи, решения по переносу и исходники компонентов с лицензиями. [Анализ пробелов](PRODUCT_GAP_ANALYSIS.md) рассматривает сквозные сценарии: запуск, подключения, сон/возврат, хранение, backup, пути проектов, уведомления и диагностику. Не все идеи становятся обязательной работой ближайшего выпуска.

## Итерация 2 — честность протокола и состояний

Разделены состояние Task, run, role assignment, ACP session и окно. Проверены границы Qwen upstream и неизвестные детали Giga. Исправлена возможность назвать роль активной до наблюдаемой доставки её инструкций; `prepared` и `active` имеют разные свидетельства. Контекстное добавление инструкций не называется заменой системного промпта.

Для managed workers и очереди зафиксированы один владелец сессии, один активный prompt, общий лимит повторов и сверка неизвестных записей. Queue pause, отмена и настоящее steering разделены. План формирует и перестраивает агент; его `completed` не означает автоматически пройденную проверку. Смена роли больше не меняет автора прежнего ответа в макете.

## Итерация 3 — проверки взаимодействий макета

Проверки выполнены через браузерный интерфейс на демонстрационных данных:

| Проверка | Наблюдение |
|---|---|
| Переключение задач | Раздельные черновики и automatic route/captured role сохраняются между A/B в текущем просмотре |
| Новая задача | Нет выдуманного выполненного плана, артефакта или ответа агента; план появится после работы |
| Вопрос | После выбранного варианта можно выбрать «Свой вариант» и отправить только свободный текст; старый выбор не добавляется к ответу |
| Очередь | Порядок, пауза, редактирование и удаление доступны; изменение queued message не уничтожает независимый черновик |
| Отмена | Показывается `cancel_requested`, без вымышленного подтверждения CLI |
| Переименование | Название сессии видно при повторном открытии; переименование вкладки меняет захваченный ID, даже если пользователь успел выбрать другую вкладку |
| Артефакт | Редактирование создаёт локальную версию с просмотром предыдущей; заголовки, списки, таблица, inline-code и fenced code отображены в примере |
| Инструменты | Общая строка и отдельные вызовы раскрываются; команда, не запущенная в макете, не получает выдуманные exit code или duration |
| Reasoning | Контрол рядом с моделью; выбранный в демонстрации уровень виден после закрытия меню. Реальные values переносятся из существующей реализации пользователя |
| Контекст | Панель открывается, закрепление материала защищает его от исключения, доступен предпросмотр контрольной точки; фактическое сжатие без CLI не объявляется выполненным |
| Геометрия и тема | Просмотрены светлая/тёмная темы; при ширине viewport 960 и 320 px ширина корня совпала со scrollWidth, на 320 px контролы не выходили по горизонтали за корень |
| Диагностика просмотра | В проверенных шагах браузерных JavaScript errors не зарегистрировано |

Исправлены обнаруженные дефекты: переименование текущей вместо исходно выбранной вкладки; сохранение старого radio choice при свободном ответе; неизменный label после переименования сессии; расхождение числа пунктов inline-плана и панели; наследование результатов пустой задачей; сдвиг composer вниз из-за высокого документа; выход меню reasoning ниже доступной области. После изменения проверен соответствующий сценарий.

## Итерация 4 — скорость работы и последние дополнения

Независимый аудит обнаружил два противоречия, оба исправлены:

- Профиль GigaCode UI требовал отдельное ревью даже для личной quick-правки. Теперь дополнительный reviewer нужен по назначенному workflow или конкретному риску, а профиль не создаёт новый обязательный процесс.
- Старый документ controls мог отключить существующий reasoning-selector при отсутствии upstream config API. Теперь приоритет имеет уже работающий adapter пользователя; проверяются его значения и перенос, а fallback относится только к новой неподдержанной возможности.

Восстановление 400/413 отдельно проверено по pinned Qwen и HTTP semantics. Учтено существующее однократное reactive compression Qwen; host не добавляет слепой повтор всего ACP prompt. Payload bytes, token window, schema error и upload error различаются. Handoff сохраняет completed/unknown effects и проверяет потери требований. Конкретную причину ошибок пользователя без его runtime установить нельзя.

В заключительном проходе добавлены обязательные интерактивные макеты M6/D7, обмен сессий и связанных проектов M4, видимая координация и параллельные ветви M5. В браузере отдельно проверено: готовый шаг действительно имеет `line-through`, у текущего задана анимация, sidebar различает работу/ожидание/результат. Адресная отмена backend-исполнителя оставила frontend работающим и показала только запрос остановки. Сообщение другому проекту сохранилось как подготовленное в макете, без ложной доставки. «Создать макет» подготовило запрос в composer, не объявило сгенерированный результат. Это проверки демонстрационных controls, не запуск агентов.

## Итерация 5 — архив, настройки и последние UX-правки

Прежний пункт меню архива заменён отдельным просмотром с поиском, типами объектов, отдельной корзиной, сохранённым планом/артефактом и восстановлением. Настройки теперь имеют разделы, app/project/task scope, происхождение значений, наследование и несохранённый draft. Контракты AR/SC задают реальные транзакции, восстановление и этапы M3/M4/M10; локальный preview этих гарантий не доказывает.

Вопрос перенесён в Task-bound overlay с вариантами, свободным ответом и сворачиванием. Служебный обмен между сессиями скрыт из обычного UI и работает через автоматический broker. Включены ранний проводник M3.14, создание собственных профилей M4.9 и автономная библиотека повторяемых helpers M4.10. 14 встроенных профилей, 29 workflows и 12 текстовых источников скриптов не заменены фиктивной native-реализацией.

Браузер получил вкладки с крестиком, переименование из контекстного меню/double-click/F2, адресную строку с Enter, внешний браузер, размеры, ориентацию, масштаб и разворот рабочей области. Канонический контракт различает фактический CSS viewport, DPR, fit preview, масштаб страницы и OS fullscreen. В макете нет живого Electron WebContents; внешние переходы и эмуляция DPR не объявляются выполненными.

При независимом просмотре найден и исправлен перенос черновика собственного профиля в чужую Task: теперь draft фиксирует исходную Task. При визуальной проверке обнаружена и исправлена ширина развёрнутого браузера, которую ограничивало старое правило расположения панели. Эти находки подтверждают необходимость проверки состояния и геометрии после действия, а не только наличия обработчика.

Для каждой функции есть [карта реализации](UI_IMPLEMENTATION_MAP.md), карточки и критерии приёмки, а [план](GIGACODE_UI_DEVELOPMENT_PLAN.md) и [поставки](DELIVERY_AND_DOGFOOD_PLAN.md) задают последовательность. Макет не является готовым desktop-приложением.

## Границы макета

В дополнительном независимом проходе оценена ежедневная работа пользователя, а не количество кнопок. Приняты [четыре небольших улучшения](DAILY_WORK_REFINEMENTS.md): сводка существенных изменений после возвращения, адресный разбор ошибки, удобный переход к конкретному результату и отложенная Task из рекомендации. Они привязаны к существующим этапам и owners. Большие новые dashboards и постоянные LLM-сводки отклонены как лишняя сложность и расход.

Макет показывает взаимодействия, а не работающий desktop backend. Нет процессов CLI/PTY, настоящих browser sessions, генерации макетов моделью, реальной компрессии, provider reasoning apply или долговечной базы приложения. Локальные примеры не являются результатами пользовательской задачи. Полный Markdown/GFM и потоковая обработка должны быть реализованы по [TRANSCRIPT_AND_MARKDOWN](TRANSCRIPT_AND_MARKDOWN.md); небольшой renderer примера не является готовой библиотекой для переноса.

Native drag через управляющий инструмент не подтвердил полноценный перенос отдельных вкладок: этот сценарий остаётся `not_verified`, а не pass. Код макета демонстрирует перенос группы панели; независимый tab docking, клавиатурный эквивалент и живые Electron views требуют приёмки M3. Сохранение между просмотрами частичное: это не доказательство crash recovery. Экспорт DOCX/PDF и downloads не объявлены проверенными по наличию кнопок.

При реализации читать только документ нужной функции и текущую карточку. Этот аудит не добавляет обязательный полный прогон после каждой малой правки. Снимки интерфейса и их назначение — в [UI_PREVIEW_GUIDE](UI_PREVIEW_GUIDE.md).
