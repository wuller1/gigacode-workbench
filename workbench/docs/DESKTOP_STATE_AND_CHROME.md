# Стабильное состояние desktop и собственная рамка окна

План для личного GigaCode UI; актуальность источников — 2026-10-09. Исходники и работающая сборка пользователя здесь недоступны. Симптомы «обновляется после клика» и «пропадает до reload» подтверждены сообщением пользователя; их причина **не установлена**. Версии Electron, Chromium, renderer framework и Windows сначала снять на целевой машине. Документация `latest` ниже не доказывает наличие API в установленной версии. GigaCode CLI не изменять.

Это дополнение к [основному плану](GIGACODE_UI_DEVELOPMENT_PLAN.md), [независимым сессиям](PARALLEL_SESSIONS_FIX.md) и [панелям](PANELS_AND_IDE.md). Режим — `personal_fast`: небольшой воспроизводимый сценарий, локальное исправление, живая проверка. Не вводить производственный процесс согласований и не переписывать приложение ради предположения.

## Порядок небольших заданий

| Карточка | Изменение | Доказательство завершения |
|---|---|---|
| M0-D1. Зафиксировать сбой | Найти реальные владельцы окна, CLI, store и подписок; записать версии/buildId. Воспроизвести без кликов и reload | Лог одной цепочки и снимок экрана; либо честное `not_reproduced` |
| M0-D2. Найти потерянную границу | Добавить временные счётчики owner → IPC → store → DOM; отдельно lifecycle окна/renderer | Видно, на какой границе перестаёт меняться sequence, либо DOM меняется, а изображение нет |
| M1-D1. Исправить одну причину | Минимальное изменение доказанного владельца/подписки/store; не новый session manager | Старый сценарий ломается на исходной версии, проходит на исправленной; соседний чат продолжает работать |
| M1-D2. Восстановление представления | Snapshot + упорядоченный хвост, reconnect, dispose подписок | Повторное открытие окна восстанавливает текущую проекцию без повторного prompt и дублей событий |
| M3-D1. Своя рамка | Отключить стандартное меню, добавить собственные кнопки/drag region и main-owned WindowService | Проверены кнопки, клавиатура, resize, DPI и выбранная политика закрытия на реальной Windows |

Исправление состояния предшествует косметической рамке. Каждая карточка указывает существующие файлы, ограниченный diff, команду запуска и наблюдаемый результат. Не добавлять абстракции, которых не требует найденная причина.

## Диагностика без угадывания причины

Сначала включить ограниченный диагностический журнал без prompt, токенов и содержимого файлов: `buildId`, версия процесса, `windowId`, `webContentsId`, `connectionGeneration`, `chatId`, `sessionId`, `operationId`, `streamId`, `seq`, `revision`, `boundary`, время. Это **внутренние поля оболочки**, не выдуманное расширение ACP. Измерять интервалы в одном monotonic clock; не вычитать несогласованные часы разных процессов.

Воспроизведение: два окна A/B, детерминированный безопасный поток событий, 10 секунд без движения мыши, кликов и клавиатуры. Затем отдельно focus/blur, minimize/restore, переход A→B→A, скрытие/открытие панели, disconnect/reconnect. Зафиксировать, исчезает ли всё окно, только содержимое, отдельная панель или лишь новые сообщения. Не использовать автоматический клик, который маскирует дефект.

| Наблюдение | Что проверить в существующем коде |
|---|---|
| Owner перестал публиковать | Блокировка main/worker, незавершённая очередь, ошибка без обработчика; не объявлять renderer виновным |
| Owner публикует, нужное окно не получает | Потерянная подписка, неверный адресат через глобальное activeWindow/currentChat, старое connection generation; глобальный `removeAllListeners` удаляет чужие callbacks |
| IPC приходит, store не меняется | Неверный ключ сущности, stale closure, отбрасывание текущего события как старого, sequence из другого потока |
| Store меняется, DOM не меняется | Мутация объекта с прежней ссылкой, selector/memo equality, подписка на другой store, некорректный cleanup/re-subscribe |
| DOM актуален, пиксели старые/пустые | CSS visibility/opacity/размеры, layout, compositor; bounds/show/hide нативного browser view поверх DOM; подтвердить снимком и размерами |
| Содержимое исчезло | Сопоставить исключение renderer, `render-process-gone`, `unresponsive`, `destroyed`, загрузку/preload; отдельно `hide`, `closed`, `isDestroyed` и main registry самого окна |

`render-process-gone` сообщает о неожиданном завершении renderer; это отличается от живого DOM, скрытого CSS или другой поверхностью. Подключить доступные текущей версии события `did-fail-load`, `preload-error`, `unresponsive`/`responsive`, `destroyed` и ограниченное логирование renderer errors. Не смешивать запись об уничтоженном `webContents` с уничтожением объекта окна. [Electron webContents](https://www.electronjs.org/docs/latest/api/web-contents).

Не принимать за исправление `forceUpdate` по mouseup, периодический reload, пересоздание CLI при focus, безусловное отключение GPU или `backgroundThrottling`. По документации throttling фоновых animations/timers включён по умолчанию; это повод измерить поведение скрытого окна, а не выключать механизм во всём приложении. Транспорт, persistence и очередь не должны зависеть от renderer timers. При возвращении видимости допустима сверка snapshot; она не заменяет подписку в видимом окне. [BrowserWindow options](https://www.electronjs.org/docs/latest/api/structures/browser-window-options).

## Один владелец состояния, окна — подписчики

```text
Existing main/backend/worker owner → persisted event + versioned IPC
  → renderer store → selectors → DOM → наблюдаемое изображение
```

Сохранить существующий единственный WorkflowEngine/SessionService. Ни окно, ни новая рамка не получают второй автомат состояний задачи. `ready` workflow не означает отсутствие работающего CLI turn; connection, turn, task и window имеют разные состояния.

1. Зафиксировать scope последовательности: `streamId + generation + seq`. IPC schema имеет версию. `revision` сущности служит CAS для команд, `seq` — доставке событий; они не взаимозаменяемы. После фильтрации общего event log нельзя объявлять каждый пропуск номера потерей: использовать последовательность данного канала или явный cursor/watermark протокол.
2. Устранить гонку snapshot/subscribe: backend атомарно фиксирует snapshot с cursor S и предоставляет хвост после S, либо подписчик сначала буферизует события и затем применяет snapshot + хвост. Если хвост уже удалён, явно запросить новый snapshot. Поздний snapshot не перетирает более новое состояние.
3. Повтор одного внутреннего event ID не добавляет второй блок; позднее событие старого connection generation отклоняется. При разрыве последовательности требуется resync. Одинаковый текст двух ACP chunks сам по себе не является дублем.
4. Подписка возвращает собственный disposer. Detach удаляет только её callbacks, не чужие. Повторное открытие создаёт подписчика, а не CLI-процесс; closing renderer не отменяет turn. Main registry явно удерживает и удаляет реальные окна по lifecycle.
5. Renderer применяет snapshot согласованно. Если проект использует React, проверить `useSyncExternalStore`: стабильная subscribe, cleanup, cached snapshot без изменений и новая immutable identity при изменении. Для другого framework использовать его существующий реактивный механизм, не переносить приложение на React. [React contract](https://react.dev/reference/react/useSyncExternalStore).
6. Команды имеют operationId, проверку владельца и ожидаемую revision; повтор доставки не повторяет dispatch. После неизвестного исхода — reconciliation, а не повтор всего prompt. Reload окна разрешён как аварийное действие пользователя после сохранения диагностики, но не как механизм обновления данных.

## Собственные кнопки и отсутствие File menu

Выбор пользователя — **полностью собственная рамка и кнопки внутри UI**. Базовый вариант: непрозрачное resizable `BrowserWindow` с `frame: false`. Это убирает штатные window controls. `titleBarStyle: 'hidden'` + `titleBarOverlay` — другой вариант с нативными кнопками; он не выполняет требование собственных нарисованных кнопок и не должен включаться поверх них. На macOS hidden может сохранить traffic lights; переносить это поведение на Windows нельзя. [Frameless windows](https://www.electronjs.org/docs/latest/tutorial/custom-window-styles), [Custom title bar](https://www.electronjs.org/docs/latest/tutorial/custom-title-bar).

В main выполнить `Menu.setApplicationMenu(null)` и проверить, что шаблон приложения не устанавливает default menu повторно. На Windows/Linux это убирает menu bar; без явной настройки Electron создаёт стандартные File/Edit/View/Window. Простое auto-hide недостаточно для требования: скрытая строка может вернуться при клавиатурном взаимодействии. Контекстные меню редактора допустимы внутри продукта. macOS application menu — отдельная платформенная политика, не обещать идентичную работу всех систем. [Menu API](https://www.electronjs.org/docs/latest/api/menu).

Оставить одну компактную верхнюю строку: название/контекст, команды приложения, собственные minimize, maximize/restore, close из [нашей библиотеки](ICON_LIBRARY.md). Семантика:

| Действие | Команда main | Подтверждение UI |
|---|---|---|
| Свернуть | `win.minimize()` | Фактическое состояние окна |
| Развернуть | `win.maximize()` | Событие maximize и `isMaximized()` |
| Вернуть обычный размер | `win.unmaximize()` | Событие unmaximize; прежняя геометрия |
| Восстановить свёрнутое окно | `win.restore()` | Возврат в предыдущее состояние, которое может быть maximized |
| Закрыть окно | Центральный request-close → выбранная ниже политика | Сохранение/подтверждение по реальному состоянию, затем close/hide |

`restore()` не заменяет `unmaximize()`. Иконка/подпись кнопки следуют нативным событиям, включая Windows hotkeys, а не только клику по UI. Использовать native maximize, не растягивать вручную до monitor bounds: рабочая область, taskbar и мониторы должны обрабатываться системой. [Window API](https://www.electronjs.org/docs/latest/api/base-window).

Выделить пустую область заголовка как `app-region: drag` (совместимость `-webkit-app-region` проверить на установленном Chromium). Все кнопки, поля, вкладки и их hit areas — `no-drag`: drag region не получает обычные pointer events. Не накрывать им composer или resize handles. Drag-only текст не выделяется; текст документов продолжает выделяться. [Custom interactions](https://www.electronjs.org/docs/latest/tutorial/custom-window-interactions).

Проверить native resize по четырём сторонам/углам, double-click заголовка, taskbar, `Win+Arrow`, перенос между мониторами, 100/125/150/200% DPI и restore bounds. Windows 11 Snap Layout при hover над **собственной** maximize-кнопкой не считать автоматически доступным: проверить на версии ОС/Electron; не обещать без живого результата. Не писать собственную имитацию оконного менеджера. Если нужен native overlay ради конкретного поведения ОС, это отдельное изменение выбранного дизайна, а не незаметная подмена.

Кнопки — настоящие button с локализованными accessible names, keyboard focus/Enter/Space, видимым focus и достаточной областью нажатия; glyph декоративный. Close не является submit. После удаления menu проверить Ctrl+C/V/X/Z/Y/A, поиск, command palette, new chat/window и переключение панелей. Существующие menu roles/accelerators не считать сохранёнными автоматически: нужные команды подключить к локальному command dispatcher. Не перехватывать ввод текста, IME и editor shortcuts глобально; `globalShortcut` не нужен для обычной команды активного окна. [Keyboard shortcuts](https://www.electronjs.org/docs/latest/tutorial/keyboard-shortcuts).

## Граница полномочий и закрытие

Preload предоставляет ограниченные intents `minimize`, `toggleMaximize`, `requestClose` и подписку на безопасный window snapshot. Не отдавать raw IPC, BrowserWindow или произвольное имя метода. Main проверяет schema, trusted sender frame и связывает его с **собственным** зарегистрированным окном; переданный renderer `windowId` не даёт права управлять другим окном. Встроенные сайты, preview и дочерние недоверенные frames не получают этот bridge. Sender validation и отсутствие raw Electron APIs у недоверенного контента предписаны официальным [Security guide](https://www.electronjs.org/docs/latest/tutorial/security).

Политику определить один раз в main и использовать для кнопки, Alt+F4 и системного close. Предпочтение личного инструмента: закрытие представления сохраняет черновики и не останавливает активную задачу. Для последнего окна явно решить: оставить backend с видимым способом возврата (например, проверенный tray/reopen) либо показать небольшой выбор «оставить работу / завершить приложение». Не оставлять невидимый недоступный процесс. `Quit` — отдельная команда; dirty editor buffers требуют решения, обычное сохранение чата не требует лишнего вопроса.

Если выход затрагивает активные операции, показать их и выбранное действие. Не вызывать безусловный kill/destroy ради закрытия UI; подтверждённый cancel, timeout и unknown outcome отражаются честно. Закрытие приложения с собственным main не гарантирует продолжения его worker. Защита от повторного создания manager и дублей listeners должна сохраниться при reopen/second-instance. Эта политика не добавляет выдуманный ACP detach/resume.

## Проверки, которые ловят именно этот сбой

Ниже **предлагаемые объёмы и критерии**, не уже полученные результаты и не гарантия отсутствия всех сбоев. Запускать на целевой Windows, проверяемом buildId и изолированных данных; сначала текущую сборку, затем исправленную. Не требовать полной производственной матрицы для личного UI.

| Проверка | Минимальный прогон / наблюдение |
|---|---|
| Обновление без взаимодействия | 3 прогона по 10 секунд, по 100 нумерованных локальных событий. Ни кликов, ни focus/resize/reload. Сопоставить все события owner/store и конечный DOM; UI может группировать chunks, но финальные данные не теряются |
| Два окна/чата | 2 независимых потока по 100 событий с перекрытием; по 5 переключений A→B→A. Ноль событий у чужой сущности, n/n доставлены; не путать это с тестом реального ACP |
| Lifecycle | По 5 minimize/restore и detach/reopen; число подписчиков возвращается к ожидаемому, новые CLI-процессы не появляются от одного attach |
| Reconnect и порядок | Inject gap, duplicate, old generation и delayed snapshot в тестовый adapter. Финальная проекция соответствует owner, нет отката revision и повторного dispatch |
| Пустое изображение | Во время воспроизведения сохранить screenshot + DOM bounds/state + webContents/window lifecycle. Различить crash, скрытый DOM и перекрывающую native surface |
| Рамка Windows | Min/max/unmax/close, клавиатура, drag/no-drag, края, DPI. Непроверенные мониторы/версии ОС записать как not tested |
| Закрытие | Dirty buffer, активный turn, два окна, последнее окно, явный Quit. Нет молчаливой потери текста или незаявленного kill |
| Живой путь CLI | После локального harness — реальные A/B через установленный неизменённый GigaCode; проверить обновление без кликов, переключение и выбранное закрытие |

Для latency сначала снять baseline p50/p95/max IPC receipt → DOM commit на переднем плане и время convergence после restore. DOM commit не доказывает фактический paint: при визуальном дефекте нужны screenshot/запись экрана. Предварительная цель для небольшого локального потока — p95 ≤100 мс и актуальный snapshot ≤1 с после restore; это проектные ориентиры, проверяемые на машине, а не норматив Electron. Отдельно показать sample count, workload и факт background throttling; не объявлять ускорение по одному запуску.

Сам observer проверить тремя контролями: **clean** доставляет известные N событий; **known_bad** намеренно теряет подписку/событие и обязан провалиться; **empty** не получает событий и возвращает insufficient evidence, а не pass. Эти инъекции только в тестовом harness. Итог: что воспроизведено, причина с файлом/строкой, что изменено, реальные counts/latency, что осталось unknown. Если причина не поймана — сохранить наблюдаемость и следующий узкий эксперимент, не выдавать reload за исправление.
