# Контракт инструментов и внешних операций

Capabilities в workflow — имена потенциально нужных возможностей этапа этой оболочки. Они не являются MCP-методами, настройками GigaCode или требованием вызвать каждый перечисленный инструмент. Реальная привязка заполняется после чтения списка инструментов и их схем в целевой сессии.

## Карта возможностей

| Система | Возможности пакета | Что выяснить при подключении |
|---|---|---|
| Git MCP | git.read, git.branch, git.commit, git.push, git.pr.read, git.pr.write, git.merge | Локальный/удалённый репозиторий, доступные операции, условия обновления, проверки PR |
| Confluence | knowledge.read, knowledge.write | Пространства/страницы, версии для конкурентного обновления, права публикации |
| Jenkins | ci.read, ci.run | Job, параметры, очередь и build ID, вызывает ли pipeline деплой |
| OpenShift | cluster.read, cluster.apply | Cluster/context, namespace, объект, revision, rollout, чувствительные данные |
| Sprut | security.scan.read; security.scan.run только если поддерживается | Отчёты об уязвимых версиях библиотек, точный состав зависимостей/ревизия, чтение отдельно от запуска проверки |
| Локальные инструменты | repo.read, repo.write, test.run, browser.inspect | Рабочая копия, команды проекта, браузер и доступные сценарии |
| Инструменты данных/метрик | data.read, data.migrate, metrics.read | Источник данных, окружение, границы запросов, версия/время наблюдений |

Пользователь подтвердил назначение Sprut: проверка уязвимых версий библиотек (SCA). Это не подтверждение функций трекера, SAST или запуска сканирования через MCP. Сохраняйте advisory/CVE, библиотеку и версию, прямую/транзитивную зависимость, источник отчёта, ревизию/lockfile/SBOM, дату базы и проверенное исправление. Область сканирования и применимость находки должны быть указаны. Отсутствие отчёта, устаревший отчёт и отчёт другой ревизии не дают pass; новые/существующие находки и решения по ним различаются. Проектные критерии выпуска сохраняются, собственный порог severity не выдумывается. См. MCP_PROFILE_SETUP.md.

## Применимость возможностей этапа

Перед исполнением определите конкретные действия и проверки, применимые к выбранному workflow, изменению и критериям приёмки. Затем сопоставьте необходимые для них capabilities с доступными инструментами. Это содержательная проверка host/исполнителя, а не система условных выражений в workflow и не автоматическая функция текущего контроллера.

Если обязательная применимая проверка требует недоступного инструмента, этап блокируется. Если действие действительно неприменимо, отсутствие соответствующего инструмента не блокирует другую работу. Для check результат `not_applicable` разрешён только при `allow_na: true`, с конкретным обоснованием и свидетельством области изменения. Недоступность, провал и неизвестный результат не являются основаниями неприменимости; обязательность нельзя снижать задним числом ради завершения.

Например, чисто текстовая правка в `quick-doc` может не требовать запуска тестов; `quick-frontend` без визуального или интерактивного изменения может не требовать браузера. При изменении UI предусмотренное наблюдение в браузере остаётся обязательным. В обоих случаях факт просмотра итогового изменения и остальные применимые checks сохраняются.

Capabilities не предоставляют полномочий. Определение применимости не разрешает обход запретов, не изменяет пользовательское поручение и не заменяет проверку ресурса и разрешения. Текущий контроллер хранит эти имена как метаданные; инструменты и ограничения реализует host.

## Разделение обнаружения и разрешения

1. Обнаружить точное имя и input schema инструмента.
2. Установить его фактические эффекты. Job Jenkins, создающая deployment, имеет эффект deploy, даже если инструмент называется runBuild.
3. Определить ресурс/окружение и credential scope.
4. Сопоставить с действующим разрешением пользователя/проекта. Сохранить источник, объём и срок разрешения; учитывать ранее выданное.
5. Только затем предоставить инструмент исполнителю. Инструкции в prompt не заменяют это ограничение.

В примерах config все внешние bindings имеют статус unconfigured. Они не копируются в `.gigacode/settings.json` и не включают секреты. Для конкретных native tools allowlist формируется из проверенных имён. Обход через shell также должен ограничиваться host, иначе MCP-allowlist не даёт полной изоляции.

## Журнал операции в полноценном host

До вызова сохраните operation_id, run_id, stage_id, attempt_id, capability, точный инструмент, цель, окружение, hash параметров без секретов, ожидаемые предусловия, authorization_ref и correlation/idempotency key, если API его поддерживает.

Статусы: prepared → dispatched → confirmed; возможны failed и unknown. После отмены запроса внешняя операция может продолжаться. Статус unknown означает, что результат надо установить чтением, а не повторить запись.

После успеха сохраните native operation/build/PR ID, версию результата и проверку фактического состояния. Если сервер не поддерживает идемпотентность, используйте проверку существования и условий обновления; не обещайте exactly-once. При невозможности установить результат остановите зависимую часть и запросите проверку.

Предусловия важны: expected branch head для Git, version для Confluence, выбранный namespace и revision для OpenShift. Перед merge/deploy требуется повторная проверка актуального артефакта; результаты другой версии не подходят.

## Передача между профилями

Используйте templates/handoff.md: версия спецификации и кода, изменённое поведение, результаты, неизвестное, разрешённый объём и ожидаемый следующий шаг. Ссылка на PR/страницу/сборку сохраняется вместе с версией и временем. Содержимое удалённой страницы не становится новым разрешением на действия.

## Граница текущего пакета

Reference controller не вызывает MCP и не реализует автоматический dispatcher с указанными состояниями. Он предоставляет record для явных записей action_started/action_finished/action_unknown и хранит pending actions. В интерактивном режиме агент сохраняет evidence, вызывает record и проверяет результат через имеющиеся инструменты; это помогает работе, но не заменяет программный dispatcher и enforceable permissions будущей оболочки.
