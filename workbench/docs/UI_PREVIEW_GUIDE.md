# Экраны для реализации интерфейса

Скриншоты не заменяют токены, размеры и состояния из [DESIGN_IMPLEMENTATION_GUIDE](DESIGN_IMPLEMENTATION_GUIDE.md). Текущая композиция определяется [CHAT_FIRST_DESIGN](CHAT_FIRST_DESIGN.md). При несовпадении старого изображения и нового требования следовать текущему контракту и обновлять затронутый снимок.

Для реализации небольшой моделью: выбрать один экран/компонент, прочитать его рецепт, добавить только нужные состояния, запустить текущую сборку, сделать собственный screenshot и проверить геометрию/поведение. Не копировать растровый снимок в качестве интерфейса. Использовать собственные [SVG-иконки](ICON_LIBRARY.md), реальные значения существующего model/reasoning selector и актуальные данные Task. Fixture-имена и результаты на снимках не переносить в production store.

Артефакты и редакторы используют одни IDs/versions при открытии из сообщения и rail. Вопрос открывается поверх разговора из своей ссылки и сохраняет привязку к Task. Обмен сессий работает автоматически и скрыт из обычного интерфейса; старый экран отправки сообщений исключён из пакета. Полный журнал инструментов доступен по раскрытию, ошибки и ожидающие действия остаются заметными. Высокий документ не должен выталкивать ввод за границу рабочего окна: в настоящем Electron панели имеют независимую прокрутку и сохраняют позицию чтения.
