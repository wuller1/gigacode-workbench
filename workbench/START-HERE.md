# Настройка и переход к разработке GigaCode UI

Текущая цель пользователя — GigaCode CLI **26.10.6** на Windows. Самонастройка сначала устанавливает фактические executable/version/hash и поддержанные команды; сведения старой обвязки 26.9.75 остаются историческими, а не подтверждением новой версии.

Это единая входная инструкция для агента на рабочем компьютере. Пользователь передал пакет, чтобы ты настроил Workbench, сохранил полезные прежние знания, адаптировал существующие MCP и затем сам предложил начать разработку его GigaCode UI. Исходный репозиторий UI здесь не приложен. Не проси повторить требования: они уже находятся в пакете.

## Запрос, который достаточно дать агенту

```text
Прочитай START-HERE.md в этом пакете и выполни самонастройку по нему. Сохрани полезные прежние знания, адаптируй мои существующие MCP под профили и проверь результат. Существующие репозитории повторно не настраивай. После настройки сам предложи начать работу над моим GigaCode UI по готовому плану и сохрани контекст продолжения, чтобы после перезапуска мне не пришлось ничего объяснять заново.
```

Если агент не видит этот файл, укажи его фактический путь или приложи файл. Нативный синтаксис `@` — только удобство поддерживающего его клиента; отсутствие этой функции не мешает обычному чтению файла инструментом.

## Порядок действий агента

1. Установи фактический корень пакета по этому файлу, прочитай действующие инструкции среды. Используй [SETUP-AGENT.md](SETUP-AGENT.md) как единственный процесс самонастройки. Не создавай вторую копию контроллера, не запускай onboarding существующих проектов.
2. До записи проверь, не сохранилось ли прежнее продолжение установки. Постоянное место и правила восстановления определены в [POST_SETUP_HANDOFF.md](docs/POST_SETUP_HANDOFF.md). Если настройка уже подтверждена и её входы не изменились, используй результаты; не переустанавливай пакет и не перечитывай всю память ради запуска следующей задачи.
3. Выполни нужные шаги самонастройки: подготовка исходников на целевой машине, проверки, миграция знаний с происхождением, реальные MCP bindings, сохранение полезных прежних правил, сверенный план, резервная копия и установка. Чтение этого документа не доказывает выполнения ни одного шага.
4. Проверь установленную конфигурацию и активацию правил. Сохрани карточку продолжения вне каталога поставки. Если нужен перезапуск CLI, сначала сохрани пути и checkpoint и объясни единственное нужное действие пользователю. Не завершай единственную активную сессию до сохранения контекста. В следующей сессии продолжи проверку активации с этого места.
5. Подготовь предложение работы над UI по разделу ниже. Уже известные путь проекта, runtime, MCP и результаты проверки возьми из доступного контекста и карточки; проверь актуальность нужных данных. Если репозиторий не определён, задай один вопрос о его пути на рабочем компьютере. Не сканируй весь компьютер и не считай каталог распакованного пакета репозиторием UI.
6. После принятия предложения пользователем продолжай [START-GIGACODE-UI.md](START-GIGACODE-UI.md), начиная с текущего незавершённого шага. Первые результаты — D0–D2 по [плану поставок](docs/DELIVERY_AND_DOGFOOD_PLAN.md); выдай пригодную сборку как можно раньше, затем продолжай разрешённые этапы. Не жди отдельного «продолжай» после каждого обычного действия.

## Что предложить после настройки

Сначала коротко укажи фактически установленное, подтверждённые проверки и оставшиеся ограничения. Затем предложи конкретный старт:

> Предлагаю перейти к твоему GigaCode UI. Начну с запуска существующей заготовки, диагностики обновления экрана без кликов и независимости двух сессий. Затем — восстановление после обрывов и 429. Первый результат: воспроизводимый запуск, диагностический пакет и подтверждённое воспроизведение сбоя либо точное ограничение проверки. План, требования и правила дизайна уже сохранены; повторять их не нужно. Начать?

Это содержание предложения, а не готовый отчёт об успехе. Подставь проверенный путь проекта, если он известен. Если путь неизвестен, объедини предложение с одним вопросом: «Где находится репозиторий GigaCode UI, с которого начать?» Явный ответ, предлагающий работать в конкретном репозитории, может одновременно выбрать проект и принять предложение. Простое сообщение пути само по себе не разрешает внешние публикации.

Самонастройка включает подготовку этого предложения и сохранение продолжения. Изменение кода UI начинается после принятия конкретного предложения либо при уже действующем явном поручении разрабатывать UI. «Пока не надо» сохраняется как deferred без повторных напоминаний. Если пользователь выбрал другую задачу, выполняй её; план UI остаётся доступным.

## Если что-то недоступно

Недостающий необязательный MCP или Node для дополнительных JavaScript checks не делает непригодным весь процесс. Укажи ограничение и заблокируй только зависимое действие. Если не прошла обязательная проверка установки, отсутствует нужный доступ или не активировались правила, не пиши «всё настроено»: сохрани точную причину и ближайший исправляющий шаг по [POST_SETUP_HANDOFF.md](docs/POST_SETUP_HANDOFF.md).

Пакет содержит инструкции и reference controller. Он сам не открывает новую сессию, не запускает UI, не регистрирует фоновую автоматизацию и не добавляет скрытые hooks. Действия выполняет агент с реально доступными средствами в границах поручения.
