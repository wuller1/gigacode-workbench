# Implementation contract

Target Windows 10/11, Windows PowerShell 5.1. Host: Electron + TypeScript, UI React + Vite. Do not modify Qwen/Giga CLI. No real credentials in source, fixtures, snapshots, logs or published repository. Runtime userData is outside package/repo. Builtin Workbench lives at ../workbench (full original package, 12 ready PS1, docs/assets/profiles). The packaged read-only reference root also contains `docs/suite/`, `suite/implementation-plan.json`, `design/suite-workspace-prototype.html`, and the `ui-kit/` starter. `workbench_reference` exposes only these allowlisted text namespaces, pages files at 20,000 characters, rejects path/symlink escapes, and never writes them. Legacy paths such as `CORE.md` resolve within `workbench/`.

Renderer bridge window.workbench.invoke(method, params), subscribe(event) is sole IPC. Shared types in shared/types.ts. All methods return JSON-compatible values or reject with readable error. No globals active session in backend. Events state.changed (snapshot should be fetched), terminal.data {id,data}, terminal.exit {id,exitCode}, browser.changed {id,url,title,loading,error?}. Browser failures are normalized plain text stored in tab state, survive browser.list/browser.inspect re-reads, and clear when a new main-frame load starts or navigation succeeds. UI refresh on events without click; coalesce snapshot refresh. Empty initial state: no fake sessions/results.

Backend WorkbenchService constructor options {dataDir, bundleDir, emit, mcpServersForSession?}. async init(), snapshot():AppState, async invoke(method,params):any, async dispose(). Owns persistent projects/tasks/sessions/settings/profiles/queue/messages/todos/questions/artifacts + CLI ACP. Implement these methods:

- state.get {}
- project.create {name,path}; project.update {id,name?,archived?}; project.delete {id} (metadata only, no source deletion; reject active descendants)
- task.create {projectId,title,description?}; task.update {id,title?,description?,archived?}; task.delete {id}
- session.create {taskId,title?,parentId?}; session.update {id,title?,model?,reasoning?,archived?,unread?}; session.delete {id}; session.send {id,text}; session.cancel {id}; session.recover {id,summary?} (explicit new ACP session, previous history preserved); session.compact {id} (host-owned short handoff/new session, never claim rewrite opaque CLI history). Public UI/IPC never accepts `profileId`; an internal coordinator assignment captures router-selected profile/version and delivery receipt.
- queue.sendNow {sessionId,id}: atomically prioritize, cancel current prompt and wait for its terminal response; never send concurrent ACP prompts or admit unknown. Explicit Stop overrides auto-resume; queued input survives failure/restart.
- queue.update {sessionId,id,text}; queue.delete {sessionId,id}; queue.move {sessionId,id,index}; queue.resume {sessionId}
- settings.update {patch:Partial<Settings>}; profile.save {id?,name,description,prompt}; profile.delete {id} (custom only)

`Settings.permissionMode` defaults to `auto_allow_bound`: CLI/MCP tools already exposed by the project/session binding are answered with an actual ACP `allow_*` option and never create a permission modal. `ask_each` keeps the legacy per-call question flow. Both modes preserve tool-call/result visibility and diagnostics; a missing real allow option is cancelled rather than guessed from labels.

The user never selects or pins a role manually, including for a child worker. At each safe dispatch boundary the host routes from the user request, Project purpose/stack/rules, Task goal/workflow stage/accepted decisions, active workspace and attached resource, current continuity, risk and enabled published profile metadata. It stores profile/version, factors/evidence, confidence and concise reason before composing the prompt. An orchestrator-created child captures that host decision in its assignment. A role change restarts the ACP context with a handoff checkpoint and never changes tool permissions, model or reasoning. The composer exposes selected→captured→actual read-only together with model, reasoning, context usage, and Git branch.

- question.answer {id,optionId?,text?} is the legacy baseline only; todo.replace {sessionId,items:Todo[]}; artifact.register {taskId,path,name?,kind?}; artifact.list {taskId}
- session.prepare {id}: initialize a real ACP process/new session and discover its actual catalog before the first prompt; deduplicate, preserve empty context, reject active/unknown, never send a model prompt to discover options.
- session.config {id,configId,value}: only actual discovered ACP config option, preserve busy capture
- diagnostics.export {} => {path}; memory.read {} => {text,hash}; memory.write {text,expectedHash} => {saved,hash}. Memory replacement requires the exact SHA-256 returned by the last read; a stale or missing hash raises MEMORY_CONFLICT without changing stored notes. memory.remember appends atomically without replacing existing text.

`S8-04` migrates questions without pretending that the current runtime already supports them: `question.list {taskId,sessionId}` returns one durable ordered queue and at most one active head; `question.answer {questionId,expectedRevision,answerOperationId,selectedOptionIds?,text?,attachmentVersionRefs?,confirm:true}`, `question.defer {questionId,expectedRevision,operationId,notBefore?,reason?}` and `question.cancel {questionId,expectedRevision,operationId,reason?}` return idempotent receipts. Every record carries question/revision/task/session plus exact origin assignment/attempt/generation/callback. Restart restores head/order/drafts/receipts, stale revisions are rejected, and answers never route through the globally active session. Only a validated typed `user_blocker_question` enters this queue; hidden peer/coordinator traffic cannot create user UI. The one-at-a-time overlay and full lifecycle are defined in `workbench/docs/ARTIFACTS_AND_QUESTIONS.md`.

Use shared type fields exactly. Add optional backend-specific fields locally or to persisted extensions, do not change public required shapes. Session.config supported actual metadata, no generic reasoning tiers magically applied. Config settings.model default may pass through known launch args; choose actual flags from Qwen docs. Do not silently replay potentially sent prompts. At least unit/contract tests for isolation, unknown outcome, persistence, queue/cancel and malformed frames.

Main process (root agent) adds:

- app.info {} => {version,platform,dataDir,bundleDir,referenceRoot}; app.chooseProject {} => Project|null (native dialog + service.create)
- app.chooseCli {} => {path}|null; window.minimize/maximize/close/new {}
- fs.list {projectId,path?} => [{name,path,directory,size}]; fs.read {projectId,path} => {text,path,mtime}; fs.write {projectId,path,text,expectedMtime?} => {mtime}; fs.create {projectId,path,directory?}; fs.rename {projectId,path,newPath}; fs.trash {projectId,path} (native trash only)
- git.status {projectId} => {branch,changes:[{path,status}],diff}; git.diff {projectId,path?} => {text}
- terminal.shells {} => [{id,name,path,args}]; terminal.create {projectId,shellId?} => {id,title}; terminal.list {} => [{id,title,projectId}]; terminal.write {id,data}; terminal.resize {id,cols,rows}; terminal.close {id}
- browser.create {sessionId?,projectId?,url?,title?,requestId?,reuseKey?} => {id,url,title,active}; browser.list {} => ordered owner-window tabs with active state; browser.activate {id}; browser.navigate {id,url}; browser.back/forward/reload/stop/close {id}; browser.rename {id,title}; browser.bounds {id,x,y,width,height,visible}; browser.zoom {id,factor}; browser.resetEmulation {id}; browser.emulate {id,width,height,deviceScaleFactor?,mobile?}; browser.external {id}; browser.capture {id,taskId?} => {path}; browser.inspect {id} => {url,title,text}; browser.act {id,action:'click'|'fill',selector,value?}. requestId is idempotent within one owner window + project and moves with a transferred tab; reuseKey reuses one surface per owner window + project and transfer collapses collisions. Every existing-tab operation is owner-window scoped. bounds only lays out/shows the native view and never changes active selection. Closing the active tab selects its adjacent right tab, then left. browser.changed is delivered only to the owner renderer, which refreshes the ordered list with stale-request protection.
- artifact.open {id} => {text?,url?,path,kind}; artifact.export {id}; external.open {url}; clipboard.write {text}

Browser uses native WebContentsView; placeholder area ResizeObserver sends physical logical Electron bounds in CSS px (not device-scaled). Hide all native views while modal/settings overlay covers area; restore on close. Browser network remote page must never receive app preload/IPC. Root owns actual browser/terminal services. UI can use textarea editor first, no fake LSP. Runnable HTML artifact must be isolated, unprivileged and explicit preview.

All app state initial values come from backend, no demo success. Browser-only preview may show clearly marked unavailable host + empty UI, not fictional working backend. UI framework packages root handles: react/react-dom, react-markdown, remark-gfm, @xterm/xterm/@xterm/addon-fit; icons reuse own SVG assets from ../workbench/assets. Frontend agent owns app/src/* only. Backend agent owns app/electron/service.ts, store.ts, acp.ts and app/tests/* (except root tests). Main/preload/browser/workspace/terminal/build config root owns. Qwen test agent owns work/qwen-runtime and work/live-qwen-tests only.

Operations uses `shared/operations.ts` and the existing project/task/session aggregate. Renderer invokes `ops.snapshot`, connection save/delete/probe/inventory, `ops.query`, `ops.prepare`, `ops.execute`, `ops.reconcile`, `ops.favorite`, and `ops.reveal`. Query/prepare require `expectedTargetHash` and `expectedAuthGeneration` captured from a project snapshot. Host MCP exposes six corresponding `ops_*` tools and injects scope and captured target guards from its per-session snapshot cache. The agent cannot edit connection credentials through these tools.

Prepare captures exact input, schema/auth/target generations, five-minute expiry and operation ID without performing the mutation. Execute persists dispatch intent before the outbound call and deduplicates by prepared action/operation ID. Unknown effects are reconciled read-only; fresh IDs do not bypass an unresolved write to the same target. Structured IPC failures use `OPS_ERROR:` followed by the bounded OpsError JSON; ordinary HTML failures are never rendered as successful API data. Full guide and limits: `docs/suite/OPERATIONS-RUNTIME-HANDOFF.md` in the repository root.
